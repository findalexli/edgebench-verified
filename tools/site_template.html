EdgeBench Verified

EdgeBench ranks AI agents on hard, open-ended engineering and science tasks. An agent works on each task for up to 12 hours, and an automatic grader scores its work from 0 to 100. A ranking can only be as trustworthy as those graders.

We examined the grader of every one of the 51 publicly released tasks and asked one question: if an agent does honest, correct work, does it get the score the task promises?

Short answer

For 23 of the 51 tasks, the grader has a problem that changes scores. The problems fall into four kinds:

  • correct work is scored too low;
  • wrong work is accepted;
  • the grader applies a different rule from the one the agent is told;
  • the score scale cannot be reached.

We fixed {{repair-v2}} of these tasks and checked each fix. We removed {{exclude}} that could not be fixed soundly. The other {{retain-with-note}} graders work as intended. Their notes record smaller caveats.

Background

How EdgeBench scores an agent

  1. The task. The agent receives written instructions and starter files. Examples: make a database engine faster, write a game-playing bot, prove a theorem, or infer the source of groundwater pollution from sensor readings.
  2. The grader. Each submission is checked by a hidden grader program written by the task's authors. It runs the agent's work on hidden test cases and produces a raw result, such as a cost, a speed, or a number of tests passed.
  3. The 0–100 scale. The raw result is converted to a score from 0 to 100 using reference points the authors chose for that task. These are usually a weak starting solution and a strong expert result.
  4. Many tries, best one kept. The agent can submit many times in 12 hours and sees each score. A run keeps its best score so far.
  5. The leaderboard. Each AI model gets three runs per task, and the three scores are averaged. A model's headline number is the average over tasks.

A grader can therefore go wrong in four places: what it accepts, what it rejects, how it converts the raw result to 0–100, and which submission it keeps. We found problems in all four.

Effect on the rankings

What the problems do to the published scores

EdgeBench publishes each model's score on every task. Using those numbers, we worked out how the averages over the 51 public tasks change once the problems are corrected. We did not rerun any AI model, and the agents' original submissions are not public, so only part of the effect can be calculated.

How we checked

How a suspicion became a finding

  1. Use the original grader. Every check ran on the exact grader software the leaderboard used, pulled from EdgeBench's public images and identified by a cryptographic fingerprint.
  2. Read what the agent is promised. The instructions and documents the agent receives, quoted rather than paraphrased, next to the grader's code.
  3. Show it with test submissions. For each suspected problem we wrote three submissions and ran them through the original grader:
    • a correct one, which must score as promised;
    • one that triggers the problem;
    • a wrong one, which must be rejected.
  4. Check the maths independently. Where a question is mathematical, we confirmed it a second way: exact arithmetic, a separate program, exhaustive search, or a computer proof checker. The proof checkers were Lean, which machine-checks mathematical proofs, and TLA+, which exhaustively explores every state of a small model.
  5. Follow it to the final score. A problem counts only if it changes the 0–100 score of honest work. Problems that do not are recorded as notes.
  6. Test every fix side by side. The same test submissions were graded by the original and the fixed version. The problem had to be gone, correct work had to keep its score, and wrong work had to stay rejected. Each comparison was repeated three times, and no outcome changed.

Not covered: deliberate cheating against the grader (how the benchmark isolates the grader is a design choice of its own), EdgeBench's 83 unreleased tasks, and new runs of AI models. The reviews were carried out by AI agents, and every claim is tied to a saved evidence file in the repository.

Using the fixed tasks. Each fix is a small patch plus a script that rebuilds the fixed task from the original public files, so nothing proprietary is redistributed. Scores from fixed versions are not comparable with the original leaderboard. See Applying the fixes.
