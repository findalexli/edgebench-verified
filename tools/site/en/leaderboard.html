Effect on the published leaderboard

What the corrected graders could change, and what cannot be determined from public data

EdgeBench publishes averages of valid runs after normalizing each run's best submission. The public averages do not determine a corrected leaderboard. Original per-run raw scores and submissions are unavailable. Table 3 gives conditional outer intervals, not estimates or demonstrated attainable outcomes. All intervals hold the valid-run set fixed, treat retained tasks as unchanged, and assume the stated effect directions and limits. Changed failure rates or solver responses require new evidence.

1What can and cannot be said

  • Scale intervals. Remove {{task:dabic_gravity_inversion|D-ABIC}}, convert {{task:borden_source_inversion|Borden}} with its affine scale, and enclose {{task:treant_forest|Treant}} with per-run affine bounds that survive averaging. A Treant average below 20 does not imply that all runs were on the same segment: zero-score clipping and the second segment prevent exact inversion. Every retained task includes ±0.05 publication-rounding uncertainty. No displayed midpoint is an inferred score.
  • Documented limits. The next interval adds {{n_bound}} conditional per-task limits. These include inferred {{task:pfr_formalization|PFR}} credit, not a demonstration that the actual targets were solved. The intervals are conditional on those limits and do not assert that all extremes can occur together. This interval counts the {{n_open}} direction-only fixes as zero, so any order it certifies holds only if those fixes have no effect. {{fragile_text}}
  • Portfolio sensitivity. The separate column assumes +0.3921/−0.10 for {{task:portfolio_risk_calibration|Portfolio Risk}}. Its restricted decimal sweep covers only 242 or 243 shared dates and strategy returns from −30% to +100%; 0.3913 is the largest sampled joint rise, and 0.3921 the sampled envelope with slack. Neither the grid nor Lean proves a global bound.
  • Full-domain envelope. The broadest interval lets open effects span the remaining score range in their stated directions. Portfolio receives the full 0–100 domain here. In this envelope every neighbouring pair of models overlaps, so it certifies no order. These are conditional outer limits, not confidence intervals or predictions.

2Why the true effect may be large

Several of the largest effects fall in the group whose size is unknown. {{task:integer_compression_codec|Integer Compression Codec}} measures every submission against stored reference numbers that the documented starter cannot reach; on two real submissions the original raw result was 2.4 and 3.7 times lower than the documented definition gives. In {{task:openttd_transport_ai|OpenTTD}}, a program that follows the instructions calls a function that does not exist and stops. Two features of EdgeBench's scoring make such effects larger rather than smaller. Because each run keeps its best score, a check that only sometimes over-credits still raises the run's result, and an agent that sees its scores for twelve hours is well placed to find a lenient check and keep using it. And because only valid runs are averaged, a run that a defect kills may be dropped rather than counted as zero.

3A check against real agent runs

EdgeBench has not released its runs. A third party has, however, published one run of Claude Opus 5.5 on 16 of the public tasks: four hours per task, with every submission the agent made and the score the original grader gave it. Nine of those 16 tasks are ones we fixed. The other seven we kept unchanged, so there is nothing to regrade.

Which fixes old submissions can test. A saved submission is the agent's answer to the task as it was. If a fix changes only the grader, the same answer can be given to the original grader and to the fixed one, and the comparison is fair, because the agent saw exactly the same task either way. If a fix changes what the agent sees (the instructions, a starter file, a statement to prove), the agent would have worked differently, so grading its old answers with the fixed version measures nothing.

  • Regraded: 7 tasks. Their fixes change the grader alone. We graded 314 submissions with both graders (349 paired gradings, counting repeats), using the run's own grading script and the official 4 CPUs, and recomputed each task's score with EdgeBench's rule of keeping the best submission so far. Graders that depend on timing were run three times for the submissions that decide the score. As a check on the replay, the original grader reproduced the run's recorded result exactly for all 144 submissions of the three tasks whose graders do not depend on timing.
  • Not regraded: 2 tasks. The {{task:borden_source_inversion|Borden Inversion}} fix changes only the instructions and a starter file. The {{task:lean_analysis_proofs|Lean Analysis}} grader needs a 33 GB image and 16 GiB of memory, more than our machines have, so its effect was computed from the original grader's verdict on each proof target instead.
