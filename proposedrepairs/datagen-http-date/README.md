# HTTP-date checker repair, version 2

The original checker accepts impossible calendar dates and clock values. This native-format patch replaces its shape-only match with a predicate that checks Gregorian dates, weekday agreement, ASCII format and clock bounds. V2 additionally rejects years before 1900 and permits second 60 only at 23:59 GMT.

The recorded protocol basis is [RFC 9110 §5.6.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.6.7), which takes year, day and time semantics from [RFC 5322 §3.3](https://www.rfc-editor.org/rfc/rfc5322.html#section-3.3), including a year of at least 1900. The different reviewer cites [RFC 1305](https://www.rfc-editor.org/rfc/rfc1305.html) for leap-second insertion after 23:59:59. That timing rule does not establish occurrence on an arbitrary date.

The author checked 12 inputs: six earlier false acceptances were rejected, five valid controls stayed accepted, and one future leap-second occurrence remained unclassified. A different reviewer checked 17 inputs: all **16 classified expectations matched**, with the same future-occurrence question unclassified. These sets overlap; they are not 29 distinct independently verified cases. The six V1 errors concern years 0000, 0001, 0100 and 1899, plus second 60 at noon or in the wrong minute. **Preserved corrections:** the original impossible-date finding remains. V1's claim that year 0001 was valid was wrong; its eight-valid count is retracted to seven. Year 0000 is invalid, not unresolved. V1 failed evidence remains pinned in the [manifest](manifest.json).

The [patch](repair.patch) targets `/tests/test_01_header_strategies.py`; verify the original SHA in the manifest before applying it. It adds a helper and changes the existing generated-date assertion, without adding a benchmark test or changing the scoring command. Adopting it changes the evaluator version. The full private test module is omitted; the manifest pins the original and resulting candidate.

This is an accepted **finite predicate repair**, not a complete HTTP-date validator or certified task replacement. A syntactically admissible `23:59:60` does not prove a leap second occurred on that date. These checks selected the actual predicate from source; they did not import the whole module, run Hypothesis or the generator, execute a native scorer, or measure score impact. Native strategy generation and the full patched scorer still need assessment. No finding or task-disposition count changes.
