# Lessons applied to this audit

The prepared report was left uncommitted and stopped preparation work remained
listed as active. No further scientific result was demonstrated during the
07:24–17:10 UTC interval. Earlier work did yield five original-source calls and
one task decision; the stall should not erase those results.

The two existing skills now enforce these consequences:

- A prepared result moves to conclusion or delivery; another review needs a
  changed claim, changed code or a real independent-reproduction gap.
- Setup gets one supported correction and a named ready fallback. Shared
  runner failures block only their actual consumers.
- A stopped owner is removed from active state; any live worker handle is
  recovered before another attempt.
- User changes to models, budget, deadline and scheduling update current
  instructions. Existing cadence is reconsidered rather than inherited.
- Progress counts actual task calls, findings, repairs and final decisions
  separately. Historical bookkeeping groups cannot stand in for coverage.
- Keep work directed toward tested repairs and inclusion, as well as findings.

The independent critical pass found the overstated 37-task coverage wording and
an exclusion-policy explanation gap. It also recovered already accepted native
Schemathesis repair results. These are reasons to improve the task record and
reuse evidence, rather than repeat the experiment.
