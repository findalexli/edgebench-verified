方法

我们如何检验这些结论

原始评分器上的证据、范围明确的形式化模型，以及针对具体版本的修复检验

1流程

我们要回答的问题是：按要求完成的工作，能否得到任务承诺的分数。发现缺陷、验证补丁、集成发布版本、衡量对排行榜的影响，是几个相互独立的结论。每个任务都记录了当前修复候选版本的证据和尚存的局限。

  1. 固定原版，读懂它的约定。把任务说明和公开镜像（按摘要固定）里的评分程序对照着读。记录源文件的指纹和评分路径。
  2. 使用能触发缺陷的对照。条件允许时，让正确的、触发问题的和错误的提交都在原始评分程序上跑一遍。组件检查和基于源代码的论证，与完整的任务运行分开标注。
  3. 独立检验。在能回答具体问题的地方，使用精确算术、另一个实现、穷尽搜索或形式化模型。几个 AI 审查者意见一致，并不等于有人独立复现过。
  4. 追踪到最终分数。区分实测的变化、上限和受限的数值估计。上限不一定能达到；组件层面的差异，也可能被评分流程中更早的否决掩盖。
  5. 验证修改后的版本。成对对照应当表明：触发问题的提交得到纠正；正确的工作分数不变，或者分数变化有解释；错误的工作仍然被拒绝。历史结果不能用来验收后来的修订版。完整的发布验收还要求实际的任务命令、依赖、工作镜像和评分器镜像，以及收集结果的评测框架，能在预算内配合运行。

历史上的可重复性：保存的清单中有 254 项评分对照，覆盖 30 个已修复任务，以及已移除任务的部分修复；其中 240 项运行了三次，不含 2 次准备性运行。其余 14 项只运行了一次：Datagen v2.1 和 FFmpeg v2.2 各三项对照、Exchange Core 在 4 个 CPU 下的六行（每行一次运行）、CTA v2.1 的标准答案，以及 Rust 初始代码在修复版下的得分。Lean Analysis 所用的依赖路径与它实际的评分命令不同；PFR 没有展示五个实际目标的得分恢复；Warehouse 需要评测框架的一个等待叠加层，端到端集成尚未完成。详见各修复包的验证状态。

2形式化证据及其局限

Lean 检查证明项，并报告证明依赖哪些公理。TLA+ 在配置好的有限模型里遍历所有可达状态。源代码对应关系和差分检查把这些模型与实现的行为联系起来，但这种联系本身并不是经过机器检验的等价性证明。有两个具名的 Lean 反向对照故意依赖任务中已安装的占位定义，我们不把它们当作普通证明。

保存的清单涵盖 26 个任务、25 个 Lean 文件（其中 286 个定理附有公理报告），以及 3 个 TLA+ 模型上的 20 次运行。其中 9 个修复模型归为“已证明”或“已模型检验”（其中 5 个针对修复的早期版本），5 个归为部分证明。这些是模型层面的分类，并不认证当前的 31 个修复包。保存的 Datagen 证明用的是历史上较宽松的年份范围；FFmpeg 证明对验证过程做了抽象，不涵盖 v2.2；CTA 模型以总敞口为分母，而政策规定的分母是基金净资产；Graph Node 的证明针对第一个修复（v2），不涵盖 v2.1 的 str() 键处理和重复键拒绝；College English 的模型针对 v2.1，不涵盖 v2.2 的 JSON 块选取和十进制字符串读取。SMT 的可靠性只涵盖一个受限的片段。

历史复检记录保存在 RECHECK.md 中。命令 python3 tools/check_formal.py 重新运行已发布的源文件，检查不变式结果是否符合预期，以及是否给出了所要求的公理报告。复检通过，并不能证明模型之外的行为，也不能验证模型没有覆盖的后续候选版本。

3局限

  • 范围限于 51 个公开任务；83 个尚未发布的任务，以及对评分器的蓄意攻击，不在范围内。
  • 我们没有重新运行任何 AI 模型。部分第三方提交重新评了分，但拿不到排行榜的提交。从平均分换算 Treant 的分数，在截断点或分段边界处并不精确。上限超过名次差距，也不能证明名次真的可能反转。
  • Portfolio 的 +0.3921/−0.10 包络来自一次受限的敏感性扫描，不是普遍成立的上限。Equivalence 的 9.67 分上限没有证明可以达到。Vibrating Path 零命中格式问题的影响，在 37 个用例上已经排除，在 13 个用例上仍未解决。
  • CPU 实验确立的是结果对资源敏感。只规定墙钟时限，并不等于承诺独占一个核心或同等的 CPU 秒数；限制并行度是一项明确的策略改动。大多数成对作业在 E2B 沙箱中运行；Lean Analysis 用的是一台本地主机。速度测量结果在其他环境中可能不同。
  • 以提交 83181b7f 时的状态计，32 个修复包中有 31 个在干净的机器上从零重建成功；Lean Analysis 例外，它的评分器镜像约需 45 GB 磁盘空间。之后修订过的修复包，只有后来的运行覆盖。
  • CTA 的净资产修正在原始评分命令下通过了成对原生运行，但没有给解题者的输出评分。Triangulation 重新生成的 v2.2 输入恰好覆盖其凸包。有限的对照和形式化模型不能确立整个任务的正确性。
