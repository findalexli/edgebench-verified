Jagua Nesting Optimization

已修复 jagua_nesting_optimization

评分器把相互重叠的形状当作有效布局接受。

摘要任务说明如何评分我们的发现文件

摘要

任务
把平面形状排入一条固定高度的长条中，使长条尽可能短，就像从一卷材料上裁切零件。
问题所在
形状重叠是被禁止的，但评分器漏掉了许多重叠：两个相同的形状放在同一位置，一个形状完全位于另一个之内，或一个形状滑过另一个的一半。它也从不检查某个形状是否以该实例所禁止的方式旋转。由于分数只取决于长条长度，一个有重叠的布局可以胜过所有有效布局。
影响有多大
有重叠的布局可能得分高于所有有效布局。影响大小未作测量。没有重叠的诚实布局不受影响。
我们的处理
已修复，发布新版本：评分器测量形状之间的精确重叠面积，拒绝任何大于较小形状面积百万分之一的重叠，而仅边缘接触仍被允许。它也拒绝被禁止的旋转。
形式化检验
在 Lean 4 中部分证明。对于轴对齐的矩形，修复后判据的一个闭式版本恰好拒绝那些内部重叠超出其 1e-6 容差的形状对。所建模的 slab 算法在每个已公布的反例和两个正方形的全部 441 种摆放上都与之一致。 局限：算法本身只在这些情况上做了检验；不涵盖一般多边形、旋转和长条边界。

要求智能体做什么

以下是 EdgeBench 的原始任务文本，即 tasks/jagua_nesting_optimization.json 中的 work.agent_query 字段，来自字节跳动 Seed 团队在 Hugging Face 上发布的 EdgeBench 数据集，采用 CC BY 4.0 许可。文本未作改动，仅从 Markdown 渲染为 HTML；指向任务工作区内文件的链接以纯文本显示。EdgeBench 的评测框架还会附加关于如何提交的标准说明（sforge/harness/evolve_scripts.py），此处未显示。任务说明是 EdgeBench 的原文，在所有语言版本中均以英文显示，未作翻译。

Role

You are an expert Rust optimization engineer working on a 2D irregular nesting solver built on top of jagua-rs.

Task

Read SEBENCH_TASK.md, inspect the real jagua-rs / lbf codebase, and improve the lbf optimizer. Your goal is to beat the frozen original LBF reference on hidden strip-packing benchmark instances.

Rules

  • Preserve the existing cargo run --release --bin lbf -- -i ... -p spp -c ... -s ... CLI behavior.
  • Keep outputs geometrically valid; the judge independently checks all placements.
  • Do not depend on GPU, network access, external services, or manual intervention.
  • Prefer robust deterministic improvements over overfitting public assets/.
  • Submit after meaningful changes so you can use iterative feedback.

我们的发现

完整案例：测试提交、独立检验和修复。文件路径指向代码仓库中的位置；链接在 GitHub 上打开。案例译自英文原文；如有出入，以英文原文为准。

结论： 已修复。原始评分器的有效性检查会接受图形之间的大面积重叠，例如完全重合的放置、图形套在其他图形里面，以及图形滑过另一个图形的一半，因此它无法保证获胜的排样方案确实能够切割出来。

任务要求

解题者要把多边形零件排进一条高度固定的带材中，并使带材尽可能短（窄），就像从一卷材料上切割零件一样。这叫作排样（nesting）。任务说明写道："Keep outputs geometrically valid; the judge independently checks all placements."（保持输出在几何上有效；评测程序会独立检查所有放置。）SEBENCH_TASK.md 写道 "illegal output, missing items, out-of-bounds placement, overlaps, timeout, or program crashes all result in a score of 0"（非法输出、缺少零件、越界放置、重叠、超时或程序崩溃都会使得分为零）。零件可以在边界上相接触。没有任何文档允许面积为正的重叠。类别：组合优化。

问题出在哪里

重叠被漏掉。 原始的 polygons_overlap 只在两种情况下报告重叠：两条边真正相交，或者一个多边形的某个顶点严格位于另一个多边形内部。不具备这两种性质的任何重叠都会被接受。这不是浮点误差造成的，在精确的整数坐标下也会发生。

原始评分器下的例子（整数坐标，旋转 0，带材高度 20）：

  • 两个相同的副本放在同一位置：预期被拒绝（重叠为零件面积的 100%）；实际被接受。
  • 一个正方形沿另一个等高正方形滑过一半（重叠面积 50）：被接受。
  • 一个矩形、一个三角形和一个菱形各自完全放在一个正方形内部（每个重叠面积 50）：被接受。菱形与正方形没有任何公共边。
  • 两个沿对角线错开的正方形，边真正相交：被拒绝，符合预期。
  • 一对共享一条边的零件（合法接触）：被接受，符合预期。

上面每一个被接受的重叠都占零件面积的 50–100%（面积为 100 的零件上重叠面积为 50–100），比任何舍入容差都大几个数量级。

禁止的旋转没有检查。 validate_solution 从不读取 allowed_orientations，因此会接受实例所禁止的旋转。

为什么重要：分数取决于带材宽度（再乘以一个运行时间系数，evaluate_case：score = raw * rt_mult），而不是重叠；而每个隐藏实例中都有需要多件的零件（需求量大于 1）。一个零件重叠的排样可以报告出比任何可行排样都更小的宽度。

影响有多大

对于排样中含有此类重叠的任何提交，这会改变其分数。不可行的排样被当作有效接受，并可能胜过每一个可行的排样。这一分数影响是根据代码推断的，没有用一份利用重叠的提交在完整评分器上测量。没有重叠的诚实排样不受影响。

修复

修复版只改动 jagua_task_scorer/evaluate.py：

  • 重叠检验。 新的 overlap_area 通过把平面切成竖直条带（slab 分解），精确计算两个简单多边形相交部分的面积。当相交面积超过 1e-6 × 较小零件的面积时，polygons_overlap 现在会拒绝这一对零件。边界接触的面积为零，仍然合法。
  • 旋转。 新的 orientation_allowed 检查在零件带有 allowed_orientations 字段时，拒绝旋转角（模 360°）不在其中的放置。
  • 不变的部分： 包围盒预筛选、带材边界、需求检查、分数公式、运行时间系数、参考解、资源文件和工作镜像。

分数兼容性： 没有超过容差的重叠、且只使用允许旋转的有效排样，在原始版和修复版中都能通过检查，得分完全相同。分数在三种情况下不同：

  • 排样中有一个原始版漏掉的正面积重叠。在修复版中它变为 WA，得 0 分。
  • 排样使用了禁止的旋转。
  • 排样中有一处边真正相交、但重叠低于容差，原始版会拒绝这种排样。修复版接受它，以零件面积的 1e-6 为限。

我们如何检查

  • 原始镜像中的原始评分器，按摘要固定。 测试排样在评分器镜像中通过未修改的 validate_solution 运行，参数为 --network none --memory 1g --cpus 1。
  • 独立的面积检查。 面积用 Shapely 2.2.0 和精确的闭式面积公式检查（测试排样都是整数坐标的矩形、三角形和菱形）。修复后的重叠面积例程还在随机整数多边形上与精确有理数的 Sutherland–Hodgman 裁剪（一种标准的多边形裁剪方法）做了对照：7526 次比较中 0 处不一致，最大绝对误差为 3.4e-13。
  • 原始评分器与修复版评分器的并排对照运行。 测试排样、全部 16 个计分实例上的冻结参考输出，以及完整的原始评分器，给出了上面的表格。并排对照运行重复了三次，判定没有变化（data/paired-repeatability.md）。

局限

  • 没有运行任何 AI 模型或求解器。影响只在我们编写的测试提交和反例上展示。
  • 没有任何利用重叠的提交在完整评分器上运行过。展示问题的测试排样经过的是 validate_solution，即评分器唯一的可行性检查。因此分数虚高是推断出来的，而不是测量出来的。
  • 测试排样是手工构造的实例，不是隐藏的资源文件。
  • 独立的面积检查覆盖的是凹多边形对凸多边形。成对的凹多边形只由测试排样和参考排样覆盖。
  • 修复版与原始版一样使用浮点数。它只在舍入误差范围内是精确的，而舍入误差远低于容差。
  • 除测试排样外，没有构造任何对抗性的或接近容差的排样，也没有运行更强的诚实求解器。
