摘要任务说明如何评分我们的发现文件

摘要

任务
按照一份书面规范，对 Web API 测试工具 schemathesis 的配置代码进行现代化改造；由隐藏测试对结果评分。
问题所在
规范规定 @schemathesis.metric 装饰器（一个用于注册另一个函数的函数）原样返回该函数。测试只检查它返回的是否是可调用对象，因此一个返回包装函数的版本与正确版本得分相同。
影响有多大
每次运行至多为总分的 1/160（0.625 分），方向可正可负：包装式装饰器最多损失这么多；一个正确的装饰器在该测试组只部分通过时最多多得这么多。
我们的处理
已修复，发布新版本：新增一项测试，检查函数是否被原样返回。当修复后测试组的全部 16 项测试都通过、或全部失败时，分数完全相同。
问题类别
评分逻辑错误（事实性错误）
验证状态
三次成对运行（均为 exit=0）：恒等组不变，包装器组 -1/160，不注册组如文档所述；修复包在一台干净的机器上从零重建（materialize-check-g2）。顶层 schemathesis.metric 的重新导出仍只检查是否可调用；没有对完整的解法评分。
形式化检验
在 Lean 4 中部分证明。每一个已公布的分数变化都是精确的，完全通过或完全失败的测试组在两个版本中得分相同。 局限：恒等性测试本身未被形式化。

import json
import re
from pathlib import Path

PASSED = "PASSED"
FAILED = "FAILED"
ERROR = "ERROR"


def read_text(path):
    p = Path(path)
    if not p.exists():
        return ""
    return p.read_text(errors="replace")


def parse_weights(script_text, phase_count):
    patterns = [
        r"weights\s*=\s*\[([0-9,\s]+)\]",
        r"PHASE_WEIGHTS\s*=\s*\(([0-9\s]+)\)",
    ]
    for pattern in patterns:
        m = re.search(pattern, script_text)
        if m:
            raw = re.split(r"[,\s]+", m.group(1).strip())
            weights = [float(x) for x in raw if x]
            if len(weights) >= phase_count:
                return weights[:phase_count]

    m = re.search(r"PHASES\s*=\s*\((.*?)\n\)", script_text, re.S)
    if m:
        weights = []
        for line in m.group(1).splitlines():
            line = line.strip()
            if not line or line.startswith("#"):
                continue
            line = line.strip("\"'")
            parts = line.split()
            if parts and re.fullmatch(r"\d+(?:\.\d+)?", parts[-1]):
                weights.append(float(parts[-1]))
        if len(weights) >= phase_count:
            return weights[:phase_count]

    reward_json = Path("/logs/verifier/reward.json")
    if reward_json.exists():
        try:
            data = json.loads(reward_json.read_text(errors="replace"))
            phases = data.get("phases")
            if isinstance(phases, dict):
                weights = []
                for phase in phases.values():
                    if isinstance(phase, dict) and "weight" in phase:
                        weights.append(float(phase["weight"]))
                if len(weights) >= phase_count:
                    return weights[:phase_count]
        except Exception:
            pass

    return [1.0] * phase_count


def parse_statuses(output):
    results = []
    seen = set()
    pattern = re.compile(r"^(tests/roadmap\.py::\S+)\s+(PASSED|FAILED|ERROR)\s*$", re.M)
    for name, status in pattern.findall(output):
        if name in seen:
            continue
        seen.add(name)
        results.append((name, status))
    return results


def parse_phase_number(name, fallback):
    m = re.search(r"(?:test_)?phase_?0*(\d+)\b", name)
    if m:
        return int(m.group(1))
    return fallback


def parse_phase_ratios(output):
    ratios = {}
    counts = {}
    pattern = re.compile(r"^Phase\s+0*(\d+):\s+(\d+)\s*/\s*(\d+)\s+passed\s*$", re.M)
    for n, passed, total in pattern.findall(output):
        n_i = int(n)
        passed_i = int(passed)
        total_i = int(total)
        counts[n_i] = (passed_i, total_i)
        ratios[n_i] = passed_i / total_i if total_i else 0.0

    weighted_pattern = re.compile(
        r"^\s*Phase\s+0*(\d+)\s+\(weight\s*=\s*([0-9.]+)\):\s*([0-9.]+)\s*$",
        re.M,
    )
    inline_weights = {}
    for n, weight, score in weighted_pattern.findall(output):
        n_i = int(n)
        inline_weights[n_i] = float(weight)
        ratios[n_i] = float(score)

    return ratios, counts, inline_weights


def parse_total_score(output):
    m = re.search(r"TOTAL_SCORE\s+([0-9]+(?:\.[0-9]+)?)", output)
    if m:
        return float(m.group(1))
    reward_path = Path("/logs/verifier/reward.txt")
    if reward_path.exists():
        try:
            return float(reward_path.read_text(errors="replace").strip())
        except Exception:
            pass
    return None


def main():
    output = read_text("/tmp/test_full.log")
    script = read_text("/tests/test.sh")

    statuses = parse_statuses(output)
    if not statuses:
        statuses = [("tests/roadmap.py::unknown", ERROR)]

    ratios, counts, inline_weights = parse_phase_ratios(output)
    weights = parse_weights(script, len(statuses))
    for idx, weight in inline_weights.items():
        if 1 <= idx <= len(weights):
            weights[idx - 1] = weight

    details = []
    weighted_total = 0.0
    weight_total = 0.0
    failed_names = []

    for pos, (name, status) in enumerate(statuses, start=1):
        phase_num = parse_phase_number(name, pos)
        weight = weights[pos - 1] if pos - 1 < len(weights) else 1.0
        if phase_num in ratios:
            ratio = ratios[phase_num]
        else:
            ratio = 1.0 if status == PASSED else 0.0
        contribution = weight * ratio
        weighted_total += contribution
        weight_total += weight

        if phase_num in counts:
            phase_passed, phase_total = counts[phase_num]
            message = (
                f"Phase {phase_num}: {phase_passed}/{phase_total} checks passed; "
                f"weighted contribution {contribution:.6f}/{weight:.6f}"
            )
        else:
            message = (
                f"Phase {phase_num}: status {status}; "
                f"weighted contribution {contribution:.6f}/{weight:.6f}"
            )

        if status != PASSED:
            failed_names.append(name)

        details.append(
            {
                "name": name,
                "status": status,
                "message": message,
                "score": contribution,
                "weight": weight,
            }
        )

    passed_count = sum(1 for _, status in statuses if status == PASSED)
    total_count = len(statuses)
    pass_rate = passed_count / total_count if total_count else 0.0
    total_score = parse_total_score(output)
    if total_score is None:
        total_score = weighted_total / weight_total if weight_total else 0.0

    summary = (
        f"{passed_count}/{total_count} phases passed; "
        f"weighted score {total_score:.6f}"
    )
    if failed_names:
        summary += ". Failed: " + ", ".join(failed_names[:10])
        if len(failed_names) > 10:
            summary += f" (+{len(failed_names) - 10} more)"

    result = {
        "valid": True,
        "score": total_score,
        "pass_rate": pass_rate,
        "summary": summary,
        "details": details,
        "metrics": {
            "phase_weighted_total": weighted_total,
            "phase_weight_total": weight_total,
            "source": "roadmap_structured_json",
        },
    }

    print(">>>>> Start Structured Result")
    print(json.dumps(result, ensure_ascii=False, indent=2))
    print(">>>>> End Structured Result")


if __name__ == "__main__":
    main()

结论： 已修复。Phase 3 的测试只检查 @schemathesis.metric 返回的是可调用对象，而不检查它是否原样返回该函数；在修复版测试下，一个包装器会失去一个测试项，即分数的 1/160（100 分制下 0.625 分）。

任务要求

解题者对 schemathesis 3.39.16（一个用于测试 Web API 的工具）的配置层进行现代化改造。按阶段分组的隐藏测试为结果评分。任务说明要求解题者 "Treat /app/TODO.md as the authoritative task specification."（把该文件视为权威的任务规格。）TODO.md 的 Target 3 写道："@schemathesis.metric decorator: Registers a metric function into a registry. Returns the function unchanged."（该装饰器把一个指标函数注册到注册表中，并原样返回该函数。）装饰器是这样一种函数：它接受另一个函数，并返回一个函数来代替它。TODO.md 对 @schemathesis.check 使用了同样的措辞。类别：系统与软件工程。

问题出在哪里

规则。 装饰器必须原样返回该函数。原始测试 test_metric_decorator_returns_function 只断言 callable(another_metric)。因此，一个把调用转发给原函数的包装器，与正确的装饰器得分相同。

例子。 在 Target 3 的一个最小实现上测试了 metric 的三个变体：

  • identity 注册该函数并将其返回。这是正确的。
  • wrapper 返回一个用 functools.wraps 构建的转发包装器。这很可能是错误的。
  • no_register 从不注册该函数。这显然是错误的。

在原始测试（orig）和修复版测试（repaired）下的 Phase 3 结果：

variant=identity    tests=orig     :: 15 passed
variant=identity    tests=repaired :: 16 passed
variant=wrapper     tests=orig     :: 15 passed
variant=wrapper     tests=repaired :: 1 failed, 15 passed
variant=no_register tests=orig     :: 3 failed, 12 passed
variant=no_register tests=repaired :: 4 failed, 12 passed

按规格的预期：包装器应当失去检查同一性的那个测试项。在原始评分器上的实际结果：包装器以 15/15 通过，与正确的装饰器相同。

为什么重要，以及为什么只是略微重要。 在行为上，包装器几乎等价于正确的装饰器。它保留 __name__，以正确的名称注册，返回相同的值，并能与收集器和 hypothesis.target 配合工作。唯一的区别是 decorated is original 以及 __wrapped__ 的存在。错误的实现相对正确的实现没有任何优势；它只是避免失去一个测试项。作者很可能本意就是要求同一性：Phase 6 的测试对 @check 断言了 result is my_func，但 Phase 3 没有这样的检查。

影响有多大

至多为总分的 1/160，即 100 分制下 0.625 分。分数是六个阶段上的 Σ(weight × passed/total)/10，Phase 3 的权重为 1。修复版的 Phase 3 有 16 项测试，一个通过原有 15 项中 k 项的包装器，其所得从 Phase 3 权重的 k/15 降到 k/16，损失 k/2400；当 k = 15 时为 1/160，即实测的 −0.006250。（在原来 15 项测试的阶段中，一项测试价值 1/15 × 1/10 = 1/150。）

这种计分变化并不只是扣分。一份装饰器原样返回函数、但只通过原有 Phase 3 测试中 k < 15 项的提交，所得从 k/15 升到 (k+1)/16，增益为 (15 − k)/2400。无论哪种变化，每次运行至多为 1/160。只有使用包装器装饰器的提交，或 Phase 3 只部分通过的提交，得分才会不同。

修复

  • /tests/test_03_metric_system.py 新增 test_metric_decorator_preserves_exact_function_identity。该测试断言 metric(f) is f，并在之后注销该函数。
  • /tests/test.sh 把 PHASE3_TOTAL 和 PHASE3_EXPECTED 从 15 改为 16。

权重、解析器、分数刻度和原有的 126 项测试都不变。在 task.json.in 中，只有 judge.image_tag 改变。

分数兼容性。 当提交通过修复版 Phase 3 的全部 16 项测试，或全部失败时，原始版和修复版评分器的分数相同。当 Phase 3 只部分通过时，两者不可比，因为该阶段有 16 项测试而不是 15 项，未全部通过的阶段会得到不同的比例。

我们如何检查

  • 在按摘要固定的原始公开镜像中运行原始评分器。 评分器镜像在 /app 中保存了未经修改的 schemathesis 3.39.16 初始代码，没有参考解法。每个变体和未改动的初始代码都在一个全新的 --network none 容器中，分别在原始测试和修复版测试下，通过完整的原始 judge.eval_cmd（bash /tests/test.sh 加上结构化解析器）运行。
  • 独立检查。 TODO.md 中规格的那句话（"Returns the function unchanged"，即原样返回该函数）就是参照，新增的测试直接检查它。这里不适用形式化模型。
  • 可重复性。 原始版和修复版评分器的并排对照运行重复了三次，结果没有变化（data/paired-repeatability.md）。

局限

  • 没有运行任何 AI 模型或求解器。影响只在我们编写的测试提交上展示。
  • 叠加实现是 Target 3 的最小实现，而不是该任务的完整解法，因此绝对分数只是部分得分。
  • 没有检查历史提交，因此真实解题者写出包装器式装饰器的频率尚不清楚。
  • 没有从固定的工作镜像中重新提取 TODO.md。
  • 新增的测试检查的是 schemathesis.generation.metrics.metric；TODO.md 中点名的顶层 schemathesis.metric 仍然只检查是否可调用，所以在顶层重新导出的包装器（例如用 functools.wraps）仍能通过全部三项 metric 测试，尽管 schemathesis.metric(f) is f 为假（本地探测）。要堵住这一点，需要再加一条断言并做一次新的并排对照运行。
  • 修复包在一台干净的机器上从零重建过（evidence/runs/materialize-check-g2，status: exit=0）：materialize.sh 原样运行，两个输出都与锁定值一致，构建出的镜像中是锁定的测试文件。
  • 隐藏测试没有保存在本仓库中。重新运行检查时，会从固定的评分器镜像中提取它们。
