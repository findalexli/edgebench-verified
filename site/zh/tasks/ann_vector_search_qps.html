摘要任务说明如何评分我们的发现文件

摘要

任务
在一百万个 128 维向量上实现搜索，使其每秒回答尽可能多的查询，同时仍能找到真实 10 个最近邻中的至少 95%。
问题所在
标准答案在全部 10,000 个查询上都经过核查；我们的有效测试提交和空测试提交得分与文档一致。附带说明：速度在每次评分中只测一次，且取决于机器。在同一台共享机器上，用原始评分器对同一个诚实配置评分三次，得到每秒 935 到 1,222 次查询（±13%）；分数刻度来自作者的硬件。
影响有多大
同一台机器上对同一配置的多次评分之间，速度相差 1.31 倍：在智能体得分所在的区间（23.8–59.7），相当于 100 分中的 13.9 分（每次评分约 ±7 分）。不同机器上的分数不可比较。
我们的处理
保留（附说明）：速度取决于机器；同一配置的三次评分相差 ±13%（100 分中的 13.9 分）；分数刻度是在作者的硬件上设定的，因此不同机器之间不可比较。

要求智能体做什么

以下是 EdgeBench 的原始任务文本，即 tasks/ann_vector_search_qps.json 中的 work.agent_query 字段，来自字节跳动 Seed 团队在 Hugging Face 上发布的 EdgeBench 数据集，采用 CC BY 4.0 许可。文本未作改动，仅从 Markdown 渲染为 HTML；指向任务工作区内文件的链接以纯文本显示。EdgeBench 的评测框架还会附加关于如何提交的标准说明（sforge/harness/evolve_scripts.py），此处未显示。任务说明是 EdgeBench 的原文，在所有语言版本中均以英文显示，未作翻译。

Role

You are an expert in approximate nearest neighbor (ANN) search. Your job is to maximize QPS (queries per second) on the SIFT-1M dataset (1M × 128-d vectors, 10K queries) under the ann-benchmarks framework, while keeping Recall@10 ≥ 0.95.

Repository Layout

  • run.py — evaluation driver (already present)
  • ann_benchmarks/algorithms/ — algorithm plugins; each algorithm subclasses BaseANN and registers in its own config.yml
  • ann_benchmarks/algorithms/custom/ — your slot; contains a baseline module.py (brute-force numpy) and a config.yml naming the algorithm custom
  • data/sift-128-euclidean.hdf5 — dataset (pre-downloaded, contains train and test arrays)

What To Do

  1. Read README.md, ann_benchmarks/algorithms/README.md, and look at existing algorithms (e.g. ann_benchmarks/algorithms/faiss/) for reference implementations.
  2. Improve ann_benchmarks/algorithms/custom/module.py — implement a faster fit() + query() using FAISS (faiss-cpu is pre-installed) or a custom implementation. Keep the class name Custom and the module path ann_benchmarks.algorithms.custom.
  3. You may tune hyperparameters via ann_benchmarks/algorithms/custom/config.yml (IVF nlist, HNSW M/efConstruction, PQ subquantizers, etc.).
  4. For local runs after each change: 
    python run.py --local --algorithm custom --dataset sift-128-euclidean -k 10 --runs 1 --run-disabled

    The benchmark prints QPS and recall metrics to the console. Use these to track your progress.

Optimization Directions (suggestions)

  • IVF bucketing (nlist, nprobe)
  • HNSW (M, ef, efConstruction)
  • Product Quantization (subquantizers, bits)
  • Two-level routing (IVF-HNSW, IVF-PQ)
  • Early termination on candidate scan
  • Multi-threaded search (omp_set_num_threads)

GLM-5.1 reference: 3108 QPS → 21472 QPS (6.9×) over 655 iterations.

Scoring Integrity (CRITICAL)

The evaluation system independently measures query latency and verifies search results against the ground truth. Your score is determined by the actual search performance of your algorithm.

You must NOT:

  • Read or access ground truth data (the neighbors dataset) during query execution
  • Override timing attributes or manipulate benchmark measurements (e.g., via get_additional())
  • Monkey-patch the time module or any benchmark framework internals
  • Attempt to fabricate or inflate scores through any means other than legitimate algorithmic improvements

Any attempt to manipulate scores will result in score=0 and the submission marked as hack.

Rules

  • Keep the algorithm name custom and leave its config discoverable via python run.py --list-algorithms
  • Do NOT modify run.py or any file outside ann_benchmarks/algorithms/custom/
  • Recall@10 < 0.95 on a config makes that config invalid (score = 0)
  • Final score is the highest QPS among valid (recall-passing) configs

完整案例：测试提交、独立检验和修复。文件路径指向代码仓库中的位置；链接在 GitHub 上打开。案例译自英文原文；如有出入，以英文原文为准。

结论： 保留（附说明）。诚实的提交按文档所述方式评分，但测得的速度取决于评分器所在的机器，并且在同一台机器上的多次评分之间也有波动（935–1,222 QPS，在分数刻度上相当于 13.9 分，满分 100）。

任务要求

智能体要加快近似最近邻搜索的速度：这种搜索无需与每个向量逐一比较，就能找出与查询最接近的向量。任务说明写道："maximize QPS (queries per second) on the SIFT-1M dataset (1M × 128-d vectors, 10K queries) under the ann-benchmarks framework, while keeping Recall@10 ≥ 0.95"（在 ann-benchmarks 框架下、在 SIFT 数据集上使每秒查询数 QPS 最大化，同时保持召回率不低于规定阈值）。Recall@10 是搜索找到的真实前 10 个最近匹配所占的比例。

工作在 ann_benchmarks/algorithms/custom/module.py 中进行。评分器把原始结果（换算到 0–100 之前），在这里即 QPS，按对数刻度（log_max）换算为满分 100 的分数。0 分的参考点是 3108 QPS，100 分的参考点是 21472 QPS。原始结果达到或超过 21472 QPS 的都得 100 分。类别：系统与软件工程。

我们检查了什么

对诚实的解题者，评分器正确地计算了文档所述的结果。以下检查确认它是正确的：

  • 评分器的精确答案（标签和距离）在全部 10,000 个查询上都正确。
  • 一个使用 FAISS flat 搜索（精确的暴力搜索）的正确测试提交被接受。一个空的测试提交被拒绝。
  • 召回率阈值按文档所述起作用。召回率统计的是返回的邻居 ID 与真实邻居 ID 的重合数，因此距离相同的并列项会被算作未命中：精确的 flat 搜索得到的召回率是 0.9993，而不是 1.0。上游 ann-benchmarks 的做法则是接受任何位于第 10 个真实距离以内的邻居。两者的差别最多为 0.07 个百分点的召回率。
  • 在一次评分内，评分器按文档所述保留最快的有效配置。

说明涉及的是速度测量。QPS 是在单次运行中测得的，并且取决于机器。在原始评分器上，同一个 IVF-flat 配置（一种只搜索少数几个向量簇的 FAISS 索引）在一台共享机器上评分三次，得到 935、1,222 和 1,094 QPS（相对中点 ±13%；最快的是最慢的 1.31 倍）。分数刻度的参考点（3108 / 21472）来自作者的硬件。

随任务发布的说明写道：QPS 取决于机器；在原始评分器上，同一个诚实的 IVF-flat 配置在一台共享机器上评分三次，得到 935–1,222 QPS（±13%）。在对数刻度上，对于介于两个参考点之间的提交，1.31 的速度比相当于 13.9 分（满分 100）。分数刻度的参考点来自作者的硬件，因此不同机器上的分数不可比。

影响有多大

在一台共享机器上，同一个诚实配置的原始结果在三次评分中介于 935 和 1,222 QPS 之间。刻度是对数的，100 · ln(QPS / 3108) / ln(21472 / 3108)，因此对任何介于 3108 和 21472 QPS 之间的提交，1.31 的速度比会让分数变化 13.9 分（满分 100）（每次评分约 ±7 分）。这里的测试提交都低于 3108 QPS，得分为 0，所以这一影响是从刻度算出来的，而不是在分数中观察到的。本任务已记录的智能体运行得分为 23.8–59.7 分（满分 100）（tasks/README.md），正好在这一区间内，因此该影响适用于智能体实际达到的分数段。任务保留每次运行的最佳提交（score_first），因此评分之间的波动可能抬高一次运行记录下的最佳成绩。不同机器之间的差异是否让每种算法的速度按相同比例变化，没有测试。满分 100 的分数在不同机器之间不可比，在同一台机器上重复评分也不能完全重复。

任务不做修改；上述说明随任务一起发布。

我们如何检查

  • 原始评分器。 评分器在原始公开镜像中不加修改地运行，镜像按摘要固定。运行条件为 2 个 CPU、--memory 3g、无网络，在一台共享机器上。镜像中的评分器文件 /tmp/eval_ann_search.py 与提取出的副本哈希一致。
诚实的测试提交召回率QPS
精确的 FAISS flat 搜索0.999331
FAISS IVF-flat（nlist 1024，nprobe 32）0.9777935、1,222、1,094（三次评分）
  • 测试设计。 每次评分运行一个 custom 模块，其 config.yml 列出了多个配置，因此 IVF-flat 的结果与我们编写的其他测试配置共用一个 ann-benchmarks 进程，而那些配置并不是诚实的提交。ann-benchmarks 在该进程中以随机顺序运行一次评分的各个配置，因此一个配置可能影响后面配置的计时。原始评分器上的三个 IVF 数值彼此相差不超过 1.31 倍。第四个 IVF 数值 875 QPS 来自一个修改过的评估器，这里不计入，来自该修改评估器的其他 IVF 数值也不计入。没有对单独的诚实提交重复评分。
  • 独立检查。 精确的标签和距离在全部 10,000 个查询上做了检查。

局限

  • 没有运行任何 AI 模型或解题者。分数影响只在我们编写的测试提交上展示。
  • 每个 QPS 数字都来自一台本地共享机器上的单次运行。没有在作者的硬件或专用评分机器上做任何测量。
  • 935–1,222 QPS 的波动范围来自三次评分，每次评分都在同一进程中运行了其他测试配置（见上文的测试设计），而不是来自对诚实提交的隔离重复。
  • 评分器能否防范蓄意恶意提交的篡改，不在本次发布的范围内（这是 EdgeBench 的设计选择），没有评估。

复现

  • 在固定镜像（sha256:aa2856a379c1…）中运行未修改的原始评分器，并把一个诚实的 custom/ 模块挂载到 ann_benchmarks/algorithms/custom。使用 --network none --cpus 2 --memory 3g，并在 /home/workspace/ann-benchmarks 中运行 python3 /tmp/eval_ann_search.py。
  • 本地开发时，任务说明自带的命令是 python run.py --local --algorithm custom --dataset sift-128-euclidean -k 10 --runs 1 --run-disabled。
