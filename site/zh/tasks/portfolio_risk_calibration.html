超额收益使用的公式与任务说明所述略有不同。

摘要任务说明如何评分我们的发现文件

摘要

任务
构建一个投资组合策略，在历史市场数据上进行测试，并与一个基准指数比较。
问题所在
任务说明把超额收益定义为策略的年化收益减去基准的年化收益。原始评分器却先把两者在测试期内的收益相减，再把差值换算成年化数值。所以解题者按任务说明自行核对超额收益时，看到的数字与评分器的略有不同。
影响有多大
在其假设下，一次有限的数值搜索得出的变化范围是 −0.10 到 +0.3921 分，这不是适用于所有情况的上限。在并排对照测试中，总分变化 +0.07 分。Lean 证明，在所述范围内，修复保持超额收益的符号和顺序不变。
我们的处理
评分器现在按任务说明把两个年化收益相减。并排测试的一个策略多得 0.07 分，测试过的错误提交仍为零分。数值搜索和 Lean 的排序结果，都依赖关于输入范围的明确假设。
问题类别
任务说明与评分不一致
验证状态
公式的成对对照已验证；0.3921 是一个受限的数值敏感性包络，不是普遍成立的分数上限。
形式化检验
在 Lean 4 中已证明。在所述的实数幂定义域假设下，对固定的基准，两种超额收益公式保持符号和顺序。这既不是总分排序的证明，也不是普遍成立的分数变化上限的证明。 局限：+0.3921/−0.10 的包络是一次受限的数值敏感性扫描，不是普遍成立的上限；与实现的对应是基于源代码的论证。。

我们的发现

完整案例，包括测试提交、独立检验和修复。文件路径指向代码仓库中的位置；链接在 GitHub 上打开。案例译自英文原文；如有出入，以英文原文为准。

结论： 已修复。任务说明写的年化超额收益是两个年化收益之差，原始评分器却先求两个区间收益之差，再把差值年化。修复版改用说明里的公式。我们在完整测试区间上做了一次有限范围的十进制扫描，联合上升最大为 0.3913 分，抽样包络为 0.3921 分，这不是全局上限。Lean 证明了基准和指数固定、且满足定义域假设时，超额值的排序和正负号不变，但没有证明总分排序不变。

任务要求

解题者要构建一个投资组合策略。评分器对策略做回测，也就是在历史市场数据上运行它，再与一个基准指数比较。任务说明明确规定了计算方法。

  • "Excess return = strategy annualized return - benchmark annualized return."（超额收益 = 策略年化收益 − 基准年化收益。）
  • "Information ratio = annualized excess return / tracking error."（信息比率 = 年化超额收益 / 跟踪误差。）
  • "Sortino ratio = annualized excess return / downside deviation."（Sortino 比率 = 年化超额收益 / 下行偏差。）

超额收益达到 12% 及以上，这一部分得满分；超额为负则扣分。类别：专业知识工作。

问题出在哪里

评分器用的公式和说明里的不一样。 金融上超额收益有好几种公认的定义，任务说明选的是两个年化收益之差。原始评分器却用策略的区间收益减去基准的区间收益，再用指数 252/N 把差值年化，N 是每日 NAV（资产净值）点的个数，252 是一年的交易日数。只有指数等于 1 时，两种算法才一致。

举一个小例子。设有 126 个 NAV 点，策略收益为 +20%，基准收益为 +10%。

  • 原始评分器给出 0.21。说明中的公式给出 0.23（精确值为 21/100 和 23/100）。
  • 两个值都高于 12% 的上限，所以都得 20/20。

真实的测试区间离 252 天近得多。 隐藏的测试区间固定在约 242 个 NAV 日，所以指数是 252/242 = 1.0413，而例子里是 2。126 点的例子把差距放大了约 50 倍，真实提交看到的差距要小得多。

信息比率和 Sortino 比率都是超额收益除以某个风险度量，所以也会跟着变。

另有一处小的不一致，不影响计分。导出的 annual_return 用 241 个收益区间，benchmark_annual_return 用 242 个 NAV 点。

照说明计算的解题者，自己算出的数和原始评分器给出的对不上。一个测试策略按说明公式自报超额 3.47%，原始评分器显示的是 3.44%。

影响有多大

  • 我们做了一次有限范围的 50 位十进制扫描，策略收益取 −30% 到 +100%，共有日期 N = 242 或 243。抽样得到的联合上升最大为 0.3913 分，下降最大为 0.10 分。如果在每个抽样的策略收益处允许任意风险度量，并留出舍入余量，包络是 0.3921（repairs/portfolio_risk_calibration-v2/paired/bound.out）。扫描时三个受影响的得分部分取同一个策略收益，评分器保留 4 位小数的舍入也算在内。网格和包络都证明不了网格点之间、其他日期数下或抽样收益范围以外的最大值。+0.3921/−0.10 只能当作明确声明的敏感性假设，它不是对每份有效提交都成立的上限。
  • 最大差距出现在略低于 12% 满分线的地方。一个按说明公式超额正好 12% 的策略，超额部分在原始评分器下得 20 分中的 19.85 分，在修复版下得 20.00 分（已安装的函数，paired/results.md）。
  • 策略收益在 0% 到 +100% 之间时，超额数值本身最多差约 0.56 个百分点。到 −30% 时可达约 0.71 个百分点，不过这时两种超额得分都已在下限 −10（float64 扫描，evidence/scripts/portfolio_risk_calibration/sensitivity.out）。
  • 指数为 252/N，N 是提交与基准共有的 NAV 日期数（eval_script.py:915-928）。上面的数值扫描只覆盖 N = 242 或 243，即完整的测试区间。
  • 设 a、b 分别是策略和基准的区间收益。基准固定时，只要 1 + a > 0 且 1 + a − b > 0，对任意实数指数 k > 0，两个公式给出的超额收益排序相同。再加上 b > −1，两者正负号也相同（已在 Lean 中证明，见下文）。所以修复不会按超额收益重排策略，也不会移动 0% 的扣分线。

修复

修复版改了一个文件 /home/workspace/scoring/eval_script.py 里的 2 行。原始评分器本来就在策略与基准共有的 N 个日期上，把基准年化为 (1 + b)^(252/N) − 1。修复用同样的方法、在同样的日期上把策略的区间收益也年化，再相减，得到的正是说明里的 "strategy annualized return − benchmark annualized return"（策略年化收益 − 基准年化收益）。信息比率和 Sortino 比率按说明的定义改用修正后的值。得分阈值、跟踪误差、下行偏差，以及只用于打印的导出 annual_return 都不变。任务 JSON 只改了 judge.image_tag（08fe0a4bad80 → 08fe0a4bad80-ebv-v2）。

我们如何检查

  • 我们把原始评分器和修复版评分器并排对照：两个评分器用相同输入，在全新的 E2B 工作节点上各跑三次，每个评分器容器的参数为 --network none --memory 2g --cpus 2。完整的 score.py 评五份提交，已安装的指标和计分函数跑我们写的五条 NAV 路径。三次结果完全相同（paired/results.md；作业 evidence/runs/portfolio_risk_calibration-v2-paired、-rep2、-rep3）。
  • 作为独立参照，我们用 60 位十进制算术把两个公式重算了一遍（paired/oracle.py，输出 oracle.out），结果与每个已安装函数的值一致。第 6 行的参照值按说明公式是 0.1200000000，按原始评分器公式是 0.1190841879。
  • 在幅度扫描中，paired/bound.py 用 50 位十进制算术，在 N = 242 和 243 下扫描 −30% 到 +100% 的策略收益（bound.out）。抽样得到的联合上升最大为 0.3913，留出余量后的抽样包络为 0.3921，抽样得到的下降为 0.10。这些是有限范围内的数值结果，并非全局上限。
  • 在早先的复现中，我们在评分器镜像中（--network none --memory 2g），用镜像随附的示例优化器跑了完整的原始计分流程（取自任务清单）。另在 126、243 和 252 个点、按恒定增长率增长的 NAV 路径上调用已安装的指标函数，再用评分器的计分函数，对照真实基准（242 个共有日期上为 24.80%）扫描 −30% 到 +100% 的策略收益。
  • 在 Lean 4（证明检查器）中，PortfolioOrderRealExp.lean 为说明里的公式建模，也就是只用一个指数的修复版公式。它用实数幂证明，修复版超额随策略收益严格递增（eC_strictMono），基准固定时修复版和原始公式对任意两个策略排序相同（same_order），且修复版公式与原始公式正负号相同（same_sign，单一指数且 b > −1）。这些结论对任意实数 k > 0、在 1 + a > 0 且 1 + a − b > 0 的条件下成立。定理对任意 k > 0 成立，所以修复版评分器在测试区间上的指数 252/242 和 252/243 都包括在内（实例引理 k_real_pos 检查 252/242 和 252/241；252/241 是导出的 annual_return 的指数，没有分数用到它）。FinanceExcessFx.lean 证明了 k = 2 时的恒等式。所有证明只用标准公理，没有 sorry（未证明的占位符）。

局限

  • 没有运行任何 AI 模型或解题者。完整评分器评的是我们写的一个测试策略（敞口设置是看过测试区间之后才定的）和镜像自带的示例。
  • 我们的测试策略超额只有 3.5%，没到 12% 的上限。上限处的行为是我们在自己写的 NAV 路径上调用已安装函数检查的，没有经过完整评分器。
  • +0.3921/−0.10 的敏感性情景来自一次有限范围的十进制扫描，不是全局上限的证明。Lean 只覆盖排序和正负号，不涉及变化的大小或方向。Lean 模型与代码的对应关系只靠一份标注了源码行的说明来建立。
  • 我们在这里没有审查本任务的其他潜在问题。
