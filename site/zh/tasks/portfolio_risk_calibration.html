Portfolio Risk Calibration

已修复 任务说明与评分不一致 portfolio_risk_calibration

超额收益使用的公式与任务说明所述略有不同。

摘要任务说明如何评分我们的发现文件

摘要

任务
构建一个投资组合策略，在历史市场数据上进行测试，并与一个基准指数比较。
问题所在
任务说明把超额收益定义为策略的年化收益减去基准的年化收益。原始评分器却先把两者在测试期内的收益相减，再把差值换算成年化数值，因此一个按任务说明自行核对超额收益的解题者，看到的数字与评分器的略有不同。
影响有多大
在其假设下，一次受限的数值扫描给出 +0.3921 和 −0.10 分的包络，这不是普遍成立的分数上限。成对的完整得分变化为 +0.07 分。在所述定义域内，Lean 证明超额收益的符号和顺序保持不变。
我们的处理
评分器现在按任务说明把两个年化收益相减。一个成对的策略多得 0.07 分，测试过的错误提交仍为零分。数值敏感性扫描和 Lean 的排序结果都有明确的定义域假设。
问题类别
任务说明与评分不一致
验证状态
公式的成对对照得到验证；0.3921 是一个受限的数值敏感性包络，不是普遍成立的分数上限。
形式化检验
在 Lean 4 中已证明。在所述的实数幂定义域假设下，对固定的基准，两种超额收益公式保持符号和顺序。这既不是总分排序的证明，也不是普遍成立的分数变化上限的证明。 局限：+0.3921/−0.10 的包络是一次受限的数值敏感性扫描，不是普遍成立的上限；与实现的对应是基于源代码的论证。。

我们的发现

完整案例：测试提交、独立检验和修复。文件路径指向代码仓库中的位置；链接在 GitHub 上打开。案例译自英文原文；如有出入，以英文原文为准。

结论： 已修复。原始评分器计算年化超额收益时，是把两个区间收益之差换算成年化值，而不是像任务说明所写的那样取两个年化收益之差。修复版使用说明中给出的公式。在完整测试区间上做的一次受限的十进制扫描，发现联合上升的最大值为 0.3913 分，抽样包络为 0.3921 分；这不是全局上限。Lean 证明的是：在基准和指数固定、并满足定义域假设时，超额值的排序和正负号保持不变；它不涉及总分的排序。

任务要求

解题者构建一个投资组合策略。评分器对其做回测，即在历史市场数据上运行它，并与一个基准指数比较。任务说明明确规定了计算约定：

  • "Excess return = strategy annualized return - benchmark annualized return."（超额收益 = 策略年化收益 − 基准年化收益。）
  • "Information ratio = annualized excess return / tracking error."（信息比率 = 年化超额收益 / 跟踪误差。）
  • "Sortino ratio = annualized excess return / downside deviation."（Sortino 比率 = 年化超额收益 / 下行偏差。）

超额收益达到 12% 或以上时，该部分得满分；超额为负则扣分。类别：专业知识工作。

问题出在哪里

评分器使用的公式与说明中的不同。 金融领域对超额收益有多种公认的定义，但任务说明选定了其中一种：两个年化收益之差。原始评分器却是用策略在区间内的收益减去基准在区间内的收益，再用指数 252/N 把这个差换算成年化值，其中 N 是每日 NAV（资产净值）点的个数，252 是一年的交易日数。只有当指数为 1 时，两者才一致。

一个小例子。 设有 126 个 NAV 点，策略收益为 +20%，基准收益为 +10%：

  • 原始评分器给出 0.21。说明中的公式给出 0.23（精确值为 21/100 和 23/100）。
  • 两个值都高于 12% 的上限，因此都得 20/20。

真实的测试区间要接近 252 天得多。 隐藏的测试区间固定为约 242 个 NAV 日，因此指数是 252/242 = 1.0413，而不是 2。126 点的例子使差距比真实提交所见的大约 50 倍。

原始评分器下随附的示例：

量值
策略区间收益15.87%
基准区间收益24.80%（在该提交与基准共有的 242 个日期上；在 243 个日期上为 24.28%，即并排对照各组中的日期数）
超额，原始评分器−9.284%
超额，说明中的公式−9.373%
超额得分，原始评分器 vs 说明−9.284 vs −9.373
最终总分两种情况都是 0/100：反作弊检查把其核心分清零，各项扣分（违反约束 5、反作弊 28、做空有效性 10）使总分降为 0（evidence/runs/portfolio_risk_calibration-v2-paired/result/out/summary_parsed.txt，e_example 组，两个评分器）

信息比率和 Sortino 比率都是用超额收益除以某个风险度量，因此它们也会改变。

另一处小的不一致（不影响计分）。 导出的 annual_return 使用 241 个收益区间，而 benchmark_annual_return 使用 242 个 NAV 点。

原始评分器给出的数值，并不是遵循说明的解题者自己会算出的数值。一个按说明公式自报超额为 3.47% 的测试策略，在原始评分器下显示为 3.44%。

影响有多大

  • 一次有限的 50 位十进制扫描，覆盖 −30% 到 +100% 的策略收益和 N = 242 或 243 个共有日期，发现抽样得到的联合上升最大为 0.3913 分，下降最大为 0.10 分。允许每个抽样策略收益取任意风险度量、并留出舍入余量的包络为 0.3921（repairs/portfolio_risk_calibration-v2/paired/bound.out）。扫描让三个受影响的得分部分取同一个策略收益，并包括评分器保留 4 位小数的舍入。无论是网格还是包络，都不能证明网格点之间、其他日期数下或抽样收益范围之外的最大值。+0.3921/−0.10 只能作为明确的敏感性假设使用；它不是对每份有效提交都成立的上限。
  • 最大差距出现在略低于 12% 满分线的位置。按说明公式超额恰为 12% 的策略，在原始评分器下得到超额部分 20 分中的 19.85 分，在修复版下得到 20.00 分（已安装的函数，paired/results.md）。
  • 对 0% 到 +100% 的策略收益，超额数值本身的差距至多约 0.56 个百分点；在 −30% 处可达约 0.71 个百分点，而此时两种超额得分都已处于下限 −10（float64 扫描，evidence/scripts/portfolio_risk_calibration/sensitivity.out）。
  • 指数为 252/N，其中 N 是提交中与基准共有的 NAV 日期数（eval_script.py:915-928）。上述数值扫描只涵盖 N = 242 或 243，即完整的测试区间。
  • 对固定的基准，在 1 + a > 0 且 1 + a − b > 0 的条件下，对每个实数指数 k > 0，两个公式给出的超额收益排序相同；若再满足 b > −1，则两者正负号相同，其中 a 和 b 分别是策略和基准的区间收益（已在 Lean 中证明，见下文）。修复不会按超额收益重排策略，也不会移动 0% 的扣分线。

修复

修复版改动一个文件 /home/workspace/scoring/eval_script.py 中的 2 行。原始评分器已经在策略与基准共有的 N 个日期上把基准年化为 (1 + b)^(252/N) − 1。修复以同样方式、在同样的日期上把策略的区间收益年化，再把两者相减。这正是说明中的 "strategy annualized return − benchmark annualized return"（策略年化收益 − 基准年化收益）。信息比率和 Sortino 比率按说明的定义使用修正后的值。以下内容不变：得分阈值、跟踪误差、下行偏差，以及只用于打印的导出 annual_return。在任务 JSON 中，只有 judge.image_tag 改变（08fe0a4bad80 → 08fe0a4bad80-ebv-v2）。

分数是否可比？ 不完全可比。在所述的完整区间定义域内，抽样得到的变化很小，但没有建立全局的分数差上限。只有在基准和指数固定、并满足定理假设时，按超额值的排名才保持不变；这并不说明总分排名是兼容的。

我们如何检查

  • 原始评分器与修复版评分器的并排对照测试。 两者在相同输入上运行，在全新的 E2B 工作节点上各运行三次，每个评分器容器的参数为 --network none --memory 2g --cpus 2。完整的 score.py 在五份提交上运行，已安装的指标和计分函数在我们编写的五条 NAV 路径上运行。三次运行结果完全相同（paired/results.md；作业 evidence/runs/portfolio_risk_calibration-v2-paired、-rep2、-rep3）。
  • 独立参照。 两个公式都用 60 位十进制算术重新计算（paired/oracle.py，输出 oracle.out），与每个已安装函数的值一致。对第 6 行，参照计算按说明公式给出 0.1200000000，按原始评分器公式给出 0.1190841879。
  • 幅度扫描。 paired/bound.py 以 50 位十进制算术、对 N = 242 和 243 扫描 −30% 到 +100% 的策略收益（bound.out），抽样得到的联合上升最大为 0.3913，留出余量后的抽样包络为 0.3921，抽样得到的下降为 0.10。这些是受限的数值结果，不是全局上限。
  • 早先的复现。 完整的原始计分流程（来自任务清单）在评分器镜像中（--network none --memory 2g）用镜像随附的示例优化器运行。在 126、243 和 252 个点的按恒定增长率增长的 NAV 路径上调用已安装的指标函数，并用评分器的计分函数，对照真实基准（在 242 个共有日期上为 24.80%）扫描 −30% 到 +100% 的策略收益。
  • Lean 4（证明检查器）。 PortfolioOrderRealExp.lean 对说明中的公式建模，即使用单一指数的修复版公式。它用实数幂证明：修复版超额随策略收益严格递增（eC_strictMono）；对固定的基准，修复版和原始公式对任意两个策略给出相同的排序（same_order）；修复版公式与原始公式正负号相同（same_sign，单一指数且 b > −1）；以上对每个实数 k > 0、在 1 + a > 0 且 1 + a − b > 0 的条件下成立。修复版评分器在测试区间上的指数 252/242 和 252/243 被涵盖，因为定理对每个 k > 0 成立（实例引理 k_real_pos 检查 252/242 和 252/241；252/241 是导出的 annual_return 的指数，没有任何分数使用它）。FinanceExcessFx.lean 证明了 k = 2 时的恒等式。所有证明都只使用标准公理，没有 sorry（未证明的占位符）。

局限

  • 没有运行任何 AI 模型或解题者。完整评分器的各组是我们编写的一个测试策略（其敞口设置是我们在查看测试区间之后选定的）和镜像自带的示例。
  • 我们的测试策略达到 3.5% 的超额，而不是 12% 的上限。上限是通过在我们编写的 NAV 路径上调用已安装函数检查的，而不是通过完整评分器。
  • +0.3921/−0.10 的敏感性情景来自一次受限的十进制扫描，不是对全局上限的证明。Lean 只涵盖排序和正负号，不涵盖变化的大小或方向；Lean 模型与代码之间的对应只靠一份标注源码行的说明建立。
  • 本任务中其他可能的问题没有在这里审查。
