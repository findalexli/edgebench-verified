Schemathesis Datagen Pipeline

已修复 schemathesis_datagen_pipeline

The date test checks only the format, not whether dates are real。

摘要任务说明如何评分我们的发现文件

摘要

任务
Build test-data generators for schemathesis, a tool that tests web APIs, including one that produces valid dates in the standard web date format.
问题所在
The hidden test checks only that each date has the right pattern of letters and digits. It accepts impossible dates such as 31 April, wrong weekdays, times like 24:00 and made-up month names. A generator that produces impossible dates or wrong weekdays about 90% of the time still passes all 15 tests in its group.
影响有多大
At most about 1% of the total score, only for generators that produce invalid dates or times; they get the same credit as correct generators.
我们的处理
The v2.1 judge checks calendar validity, weekday and time, and restricts years to 1900 or later. Three paired native eval_cmd controls pass: valid-generator score unchanged, pre-1900 and malformed-date generators lose the intended test credit. The old Lean proof has not been revised.
形式化检验
在 Lean 4 中已证明。The historical model checks calendar validity, matching weekday and time over years 1–9999, and its weekday arithmetic agrees with Python. That modeled domain admits years forbidden by the cited HTTP-date standard; this is not proof of the current year≥1900 v2.1 candidate. 局限：Hand-written parser; historical relaxed year domain, not standards conformance. Current v2.1 native paired grading and integration pending.。

import json
import re
from pathlib import Path

PASSED = "PASSED"
FAILED = "FAILED"
ERROR = "ERROR"


def read_text(path):
    p = Path(path)
    if not p.exists():
        return ""
    return p.read_text(errors="replace")


def parse_weights(script_text, phase_count):
    patterns = [
        r"weights\s*=\s*\[([0-9,\s]+)\]",
        r"PHASE_WEIGHTS\s*=\s*\(([0-9\s]+)\)",
    ]
    for pattern in patterns:
        m = re.search(pattern, script_text)
        if m:
            raw = re.split(r"[,\s]+", m.group(1).strip())
            weights = [float(x) for x in raw if x]
            if len(weights) >= phase_count:
                return weights[:phase_count]

    m = re.search(r"PHASES\s*=\s*\((.*?)\n\)", script_text, re.S)
    if m:
        weights = []
        for line in m.group(1).splitlines():
            line = line.strip()
            if not line or line.startswith("#"):
                continue
            line = line.strip("\"'")
            parts = line.split()
            if parts and re.fullmatch(r"\d+(?:\.\d+)?", parts[-1]):
                weights.append(float(parts[-1]))
        if len(weights) >= phase_count:
            return weights[:phase_count]

    reward_json = Path("/logs/verifier/reward.json")
    if reward_json.exists():
        try:
            data = json.loads(reward_json.read_text(errors="replace"))
            phases = data.get("phases")
            if isinstance(phases, dict):
                weights = []
                for phase in phases.values():
                    if isinstance(phase, dict) and "weight" in phase:
                        weights.append(float(phase["weight"]))
                if len(weights) >= phase_count:
                    return weights[:phase_count]
        except Exception:
            pass

    return [1.0] * phase_count


def parse_statuses(output):
    results = []
    seen = set()
    pattern = re.compile(r"^(tests/roadmap\.py::\S+)\s+(PASSED|FAILED|ERROR)\s*$", re.M)
    for name, status in pattern.findall(output):
        if name in seen:
            continue
        seen.add(name)
        results.append((name, status))
    return results


def parse_phase_number(name, fallback):
    m = re.search(r"(?:test_)?phase_?0*(\d+)\b", name)
    if m:
        return int(m.group(1))
    return fallback


def parse_phase_ratios(output):
    ratios = {}
    counts = {}
    pattern = re.compile(r"^Phase\s+0*(\d+):\s+(\d+)\s*/\s*(\d+)\s+passed\s*$", re.M)
    for n, passed, total in pattern.findall(output):
        n_i = int(n)
        passed_i = int(passed)
        total_i = int(total)
        counts[n_i] = (passed_i, total_i)
        ratios[n_i] = passed_i / total_i if total_i else 0.0

    weighted_pattern = re.compile(
        r"^\s*Phase\s+0*(\d+)\s+\(weight\s*=\s*([0-9.]+)\):\s*([0-9.]+)\s*$",
        re.M,
    )
    inline_weights = {}
    for n, weight, score in weighted_pattern.findall(output):
        n_i = int(n)
        inline_weights[n_i] = float(weight)
        ratios[n_i] = float(score)

    return ratios, counts, inline_weights


def parse_total_score(output):
    m = re.search(r"TOTAL_SCORE\s+([0-9]+(?:\.[0-9]+)?)", output)
    if m:
        return float(m.group(1))
    reward_path = Path("/logs/verifier/reward.txt")
    if reward_path.exists():
        try:
            return float(reward_path.read_text(errors="replace").strip())
        except Exception:
            pass
    return None


def main():
    output = read_text("/tmp/test_full.log")
    script = read_text("/tests/test.sh")

    statuses = parse_statuses(output)
    if not statuses:
        statuses = [("tests/roadmap.py::unknown", ERROR)]

    ratios, counts, inline_weights = parse_phase_ratios(output)
    weights = parse_weights(script, len(statuses))
    for idx, weight in inline_weights.items():
        if 1 <= idx <= len(weights):
            weights[idx - 1] = weight

    details = []
    weighted_total = 0.0
    weight_total = 0.0
    failed_names = []

    for pos, (name, status) in enumerate(statuses, start=1):
        phase_num = parse_phase_number(name, pos)
        weight = weights[pos - 1] if pos - 1 < len(weights) else 1.0
        if phase_num in ratios:
            ratio = ratios[phase_num]
        else:
            ratio = 1.0 if status == PASSED else 0.0
        contribution = weight * ratio
        weighted_total += contribution
        weight_total += weight

        if phase_num in counts:
            phase_passed, phase_total = counts[phase_num]
            message = (
                f"Phase {phase_num}: {phase_passed}/{phase_total} checks passed; "
                f"weighted contribution {contribution:.6f}/{weight:.6f}"
            )
        else:
            message = (
                f"Phase {phase_num}: status {status}; "
                f"weighted contribution {contribution:.6f}/{weight:.6f}"
            )

        if status != PASSED:
            failed_names.append(name)

        details.append(
            {
                "name": name,
                "status": status,
                "message": message,
                "score": contribution,
                "weight": weight,
            }
        )

    passed_count = sum(1 for _, status in statuses if status == PASSED)
    total_count = len(statuses)
    pass_rate = passed_count / total_count if total_count else 0.0
    total_score = parse_total_score(output)
    if total_score is None:
        total_score = weighted_total / weight_total if weight_total else 0.0

    summary = (
        f"{passed_count}/{total_count} phases passed; "
        f"weighted score {total_score:.6f}"
    )
    if failed_names:
        summary += ". Failed: " + ", ".join(failed_names[:10])
        if len(failed_names) > 10:
            summary += f" (+{len(failed_names) - 10} more)"

    result = {
        "valid": True,
        "score": total_score,
        "pass_rate": pass_rate,
        "summary": summary,
        "details": details,
        "metrics": {
            "phase_weighted_total": weighted_total,
            "phase_weight_total": weight_total,
            "source": "roadmap_structured_json",
        },
    }

    print(">>>>> Start Structured Result")
    print(json.dumps(result, ensure_ascii=False, indent=2))
    print(">>>>> End Structured Result")


if __name__ == "__main__":
    main()

Six native arms of the original evaluation command passed: the valid generator retained reward 0.477350, while the pre-1900 and garbage generators fell to 0.467094. The older results below describe historical v2; these finite controls do not certify the whole task. See follow-up.

Outcome: Original defect confirmed; v2.1 repair validated on paired native controls. The hidden test for HTTP dates checks only the shape of the string, so generators that emit impossible dates and clock times pass; the gap is worth about 1% of the score.

What the task asks

The solver builds data-generation strategies for schemathesis 4.14.3, a tool that tests web APIs. The solver is told to "Treat /app/TODO.md as the authoritative task specification." TODO.md Target 1 asks for an "HTTP-date strategy: Generate valid HTTP-date values in IMF-fixdate format". It adds: "In positive generation mode, all generated values should conform to the protocol grammar." RFC 9110 §5.6.7, the standard for HTTP dates, annotates time-of-day as 00:00:00 - 23:59:60 (leap second). It leaves the meaning of the date fields to RFC 5322 §3.3, which requires a date-time to be "semantically valid": a real day of the month, a matching weekday and a clock time in range. Category: Systems & Software Engineering.

What goes wrong

Rule. Generated HTTP dates must be valid dates in IMF-fixdate format. The original test checks each string against ^\w{3}, \d{2} \w{3} \d{4} \d{2}:\d{2}:\d{2} GMT$ and nothing else. This pattern does not check:

  • that the date exists in the calendar (31 Apr and 29 Feb 2023 do not);
  • that the weekday matches the date;
  • clock bounds, such as 24:00;
  • that the weekday and month names are real names. \w{3} accepts any three word characters, so "Abc, 99 Xyz 0000 99:99:99 GMT" passes.

Example. A realistic generator draws weekday, day, month, year and clock independently (independent_fields). It produces impossible dates and mismatched weekdays in about 90% of draws. Of 50 draws with fixed randomness, the original pattern accepted 50/50 and the fixed check 5/50. Expected from the task's specification: the date test should fail. Observed on the original grader: Phase 1 passes this generator at 15/15.

Why it matters. A wrong generator gains nothing over a correct one, but both receive the same Phase 1 credit, so the test cannot tell them apart.

How much it matters

At most about 1% of the total. The date test is 1 of 15 Phase 1 tests, and Phase 1 has weight 2/13, so the effect is −2/195 of the total. Only solvers whose http_date_values emits invalid dates or clock times are affected.

The fix

The fixed version changes one file, /tests/test_01_header_strategies.py. The pattern that checks only the shape is replaced by the check is_imf_fixdate. That check covers the IMF-fixdate grammar, a real Gregorian date, agreement of the weekday and clock bounds, and allows :60 only at 23:59. It requires only a year that can be represented (≥ 1), because TODO.md states no lowest year. The one date test's max_examples goes from 50 to 200. With 50 examples, rare clock defects (hour 24) were caught in only 15/20 random seeds; with 200 they were caught in 20/20. The number of tests, test.sh, the weights and the parser are unchanged. In task.json.in, only judge.image_tag changes.

Test generators: correct (st.datetimes(1970..2100)); stdlib_1900 and stdlib_any_year (honest generators based on email.utils.format_datetime); independent_fields and off_by_one_clock (plausible but wrong; the latter draws hour 0–24 and minute 0–60); garbage_shape (invalid test submission, "999, 99 888 0000 99:99:99 GMT"); rfc850 (test submission in the wrong format); and the untouched starter.

How we checked it

  • Original grader, from the public image pinned by digest. The grader image holds the unmodified schemathesis 4.14.3 starter with hypothesis 6.155.2 (the property-testing library) and no reference solution. Each generator ran under the full original judge.eval_cmd and under the fixed version, in fresh --network none containers. The single date test was also run with 20 Hypothesis seeds.
  • Independent check. A pure-Python check ran the original pattern and the fixed check on fixed strings: 31 Apr, 24:00, a wrong weekday, 29 Feb 2023, 29 Feb 2024 and Sat, 31 Dec 2016 23:59:60. Calendar validity was checked against Python's Gregorian calendar.
  • Repeatability. The side-by-side run of the original and fixed graders was done three times, and no result changed (data/paired-repeatability.md).

Limits

  • No AI model or solver was run. Effects are shown only on the generators we wrote.
  • The generators are a minimal overlay for Target 1. No upstream reference generator was available, so the scores are partial.
  • Whether a leap second actually occurred is not checked. :60 is allowed only at 23:59 but is not checked against the real table of leap seconds.
  • The property tests remain random. The wrong generators tested were detected in 20/20 seeds, but rarer defects could still pass a given seed.
  • How often such bugs occur in real submissions is unknown.
