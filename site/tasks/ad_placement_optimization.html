Summary

The task
Place one rectangle per company on a 10000 x 10000 grid so each covers its company's point, has close to the requested area, and overlaps no other rectangle.
What goes wrong
No material problem. Shared edges and corners are accepted, overlaps and out-of-bounds rectangles are rejected, and every case is scored as the contest rules say. Caveats: the 50 graded inputs are public examples, not hidden; the score scale's reference points come from contest results on other inputs and were not checked; the effect of available computing power was not measured.

Ad Placement Optimization

You need to place rectangular ads for n companies on a 10000x10000 grid.

Each company i wants an ad space containing point (x_i+0.5, y_i+0.5) with area as close to r_i as possible. Maximize the total satisfaction.

Full problem description, constraints, scoring formula, and input/output format are in README.md.

Local Testing Tools

tools/ provides an input generator and scoring program. The generator reads a seed file and writes generated cases into a directory; it does not accept a raw seed directly.

# Generate one test input
printf '0\n' > /tmp/seeds.txt
rm -rf /tmp/ad_cases && mkdir -p /tmp/ad_cases
./tools/bin/gen /tmp/seeds.txt -d /tmp/ad_cases
cp /tmp/ad_cases/0000.txt input.txt

# Run your solution
./my_solution < input.txt > output.txt

# Score it
./tools/bin/tester input.txt output.txt
# stderr: Score = <number>

For multiple local cases, put one seed per line in the seed file, for example seq 0 9 > /tmp/seeds.txt, then run ./tools/bin/gen /tmp/seeds.txt -d /tmp/ad_cases.

You can generate unlimited test data with any seed value. Use this extensively for local testing and optimization.

Compilation

Recommended: C++17 with g++ -std=c++17 -O2.

Time limit: 5 seconds per test case. Memory limit: 1 GB. No GPU.

Rules

  • Write your solution as a single C++ file in the project root directory
  • Do NOT modify files in tools/
  • Use tools/bin/gen with a seed file and tools/bin/tester for local testing
  • Your program should read from stdin and write to stdout
  • Run your solution to completion and verify with the tester before finishing

What we found

The full case: the test submissions, the independent checks and the fix. File paths refer to the repository; links open on GitHub.

Outcome: Kept, with a note. The original grader applies the rules of the AtCoder contest AHC001 correctly, and no problem found can score an honest solver wrongly.

What the task asks

The solver places one rectangle per company on a 10000x10000 grid. The task statement says: "Each company i wants an ad space containing point (x_i+0.5, y_i+0.5) with area as close to r_i as possible. Maximize the total satisfaction." The README says that "Different rectangles may share edges but must not overlap (common area must be zero)", and that "Final score = sum of scores across all 50 public test cases". Category: Combinatorial Optimization.

What we checked

There is no problem that changes scores. We checked the rules that decide whether an output is legal:

  • Shared edges and shared corners are accepted. For example, the test outputs edge_touch and corner_touch each scored Score = 1000000000, the same as the independent reference implementation (the "oracle").
  • Any overlap with positive area is rejected when the later-indexed rectangle of the pair contains its own point. This includes a single unit cell, a contained rectangle and identical rectangles. Each was reported as wrong answer, with overlap as the reason.
  • Bounds, positive area and point containment are checked exactly.
  • A timeout, runtime error or wrong answer scores 0 for that case. The case is still listed and is never silently dropped. This matches the AHC001 system-test rule.

One ordering quirk, inherited from the contest code, gives an honest solver nothing. The grader and the oracle disagree on 1 of 23 hand-written outputs. That output contains a rectangle that misses its own point, so it already scores p_i = 0. Whether its overlap is checked depends on the order of the output. The official AHC001 code behaves the same way. The overlap itself earns nothing; the most a solver could gain is room it would otherwise have to free, which a valid output can recover at a cost of at most about 0.004 points out of 100 per affected company per case (evidence/reviews/ad_placement_optimization.md, "Does it accept real overlaps?").

The note says:

  1. The 50 graded inputs are the public generator seeds 0–49. These are also the official AHC001 example inputs. They are not held out.
  2. Two reference points of the 0–100 scale (the "rank30" and "rank1" points) come from AtCoder results on different inputs. Their source was not checked.
  3. The grader runs min(nproc,2) cases in parallel. nproc ignores a Docker CPU quota, and the task sets no cpu_limit. So the computing power available to a time-limited solver depends on how many CPUs the grader's machine gives it. The size of this effect was not measured.

Not in the shipped note:

  • The 5 s limit is wall-clock time (timeout 5 in eval_ahc.sh). A solver that budgets about 4.9 s of CPU time (for example with clock()) needs about 9.8 s of wall time when two cases share one CPU, and gets a timeout, which scores 0 for that case. A solver that budgets wall-clock time finished in time at --cpus 1 (timing check below).
  • The task text states "Memory limit: 1 GB". The grader does not enforce it: eval_ahc.sh sets no memory limit and the task sets no mem_limit.

How much it matters

The largest score change for an honest solver from the scoring rules is 0 (an output that exploits the ordering quirk gains at most about 0.004 points per affected company per case). The effect of CPU allocation is not measured: on a grader with less than 2 CPUs of quota, a solver that budgets CPU time rather than wall-clock time can time out on every case. The other note items (public inputs, origin of the score scale, unenforced memory limit) affect how scores should be read, not how any output is scored.

How we checked it

  • Original grader, from the public image pinned by digest. It ran with --network none --memory 2g --cpus 2|1, one container at a time. Seven test submissions, each built to exercise one rule, ran on all 50 grading cases, giving 350 per-case results. Every per-case status and score equals that of an exact-fraction oracle written from the README:

  • Small hand-written outputs. 23 hand-written outputs ran through the original grader program and were compared with the oracle. They cover shared edges, shared corners, overlaps, out-of-range coordinates, zero area, malformed tokens and whitespace variants.
  • Source comparison. The task's scoring source matches the scoring code of the official AHC001 visualizer statement by statement. The only differences are in input parsing and in how invalid output is reported.
  • Timing check. A solver that busy-waits until 4.9 s of wall time ran at --cpus 2 and at --cpus 1.
  • Data. The image's own generator, run on seeds 0–49, reproduces all 50 grading inputs byte for byte. These equal the official AHC001 example inputs. A separate scan of the input constraints found no failures and no byte-identical duplicates.

Limits

  • No AI model or solver was run. Score effects are shown only on the test submissions and counterexamples we wrote.
  • The grader program was not rebuilt from source. That the source and the program behave the same is inferred from matching behaviour on every branch exercised.
  • No real optimizing solver was run, so the effect of CPU allocation on scores is not measured. The timing check used a wall-clock spin, which cannot show the effect on a solver that budgets CPU time.
  • The origin of the rank30 and rank1 reference points, and whether they are comparable to seeds 0–49, was not checked.
