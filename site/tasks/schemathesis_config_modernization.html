Schemathesis Config Modernization

Fixed Grader correctness and factual errors schemathesis_config_modernization

One test does not check that a function is returned unchanged.

SummaryThe instructionsHow it is gradedWhat we foundFiles

Summary

The task
Modernize the configuration code of schemathesis, a tool for testing web APIs, following a written specification; hidden tests grade the result.
What goes wrong
The specification says the @schemathesis.metric decorator (a function that registers another function) returns the function unchanged. The test only checks that it returns something callable, so a version that returns a wrapper scores the same as a correct one.
How much it matters
At most 1/160 of the total (0.625 points) per run, either way: a wrapper decorator loses up to that; a correct one with that test group partly passed gains up to that.
What we did
Fixed in a new version: the fix adds one test that checks the function comes back unchanged. Scores are identical when all 16 tests of the fixed test group are passed, or all are failed.
Problem category
Grader correctness and factual errors
Validation status
Three paired runs (each exit=0): identity arm unchanged, wrapper arm -1/160, no-register arm as documented; package rebuilt from scratch on a clean machine (materialize-check-g2). The top-level schemathesis.metric re-export is still checked only for callability; no complete solution graded.
Formal check
Partly proved in Lean 4. Every published score change is exact, and fully passed or fully failed test groups score the same in both versions. Limit: The identity test itself is not formalized.

import json
import re
from pathlib import Path

PASSED = "PASSED"
FAILED = "FAILED"
ERROR = "ERROR"


def read_text(path):
    p = Path(path)
    if not p.exists():
        return ""
    return p.read_text(errors="replace")


def parse_weights(script_text, phase_count):
    patterns = [
        r"weights\s*=\s*\[([0-9,\s]+)\]",
        r"PHASE_WEIGHTS\s*=\s*\(([0-9\s]+)\)",
    ]
    for pattern in patterns:
        m = re.search(pattern, script_text)
        if m:
            raw = re.split(r"[,\s]+", m.group(1).strip())
            weights = [float(x) for x in raw if x]
            if len(weights) >= phase_count:
                return weights[:phase_count]

    m = re.search(r"PHASES\s*=\s*\((.*?)\n\)", script_text, re.S)
    if m:
        weights = []
        for line in m.group(1).splitlines():
            line = line.strip()
            if not line or line.startswith("#"):
                continue
            line = line.strip("\"'")
            parts = line.split()
            if parts and re.fullmatch(r"\d+(?:\.\d+)?", parts[-1]):
                weights.append(float(parts[-1]))
        if len(weights) >= phase_count:
            return weights[:phase_count]

    reward_json = Path("/logs/verifier/reward.json")
    if reward_json.exists():
        try:
            data = json.loads(reward_json.read_text(errors="replace"))
            phases = data.get("phases")
            if isinstance(phases, dict):
                weights = []
                for phase in phases.values():
                    if isinstance(phase, dict) and "weight" in phase:
                        weights.append(float(phase["weight"]))
                if len(weights) >= phase_count:
                    return weights[:phase_count]
        except Exception:
            pass

    return [1.0] * phase_count


def parse_statuses(output):
    results = []
    seen = set()
    pattern = re.compile(r"^(tests/roadmap\.py::\S+)\s+(PASSED|FAILED|ERROR)\s*$", re.M)
    for name, status in pattern.findall(output):
        if name in seen:
            continue
        seen.add(name)
        results.append((name, status))
    return results


def parse_phase_number(name, fallback):
    m = re.search(r"(?:test_)?phase_?0*(\d+)\b", name)
    if m:
        return int(m.group(1))
    return fallback


def parse_phase_ratios(output):
    ratios = {}
    counts = {}
    pattern = re.compile(r"^Phase\s+0*(\d+):\s+(\d+)\s*/\s*(\d+)\s+passed\s*$", re.M)
    for n, passed, total in pattern.findall(output):
        n_i = int(n)
        passed_i = int(passed)
        total_i = int(total)
        counts[n_i] = (passed_i, total_i)
        ratios[n_i] = passed_i / total_i if total_i else 0.0

    weighted_pattern = re.compile(
        r"^\s*Phase\s+0*(\d+)\s+\(weight\s*=\s*([0-9.]+)\):\s*([0-9.]+)\s*$",
        re.M,
    )
    inline_weights = {}
    for n, weight, score in weighted_pattern.findall(output):
        n_i = int(n)
        inline_weights[n_i] = float(weight)
        ratios[n_i] = float(score)

    return ratios, counts, inline_weights


def parse_total_score(output):
    m = re.search(r"TOTAL_SCORE\s+([0-9]+(?:\.[0-9]+)?)", output)
    if m:
        return float(m.group(1))
    reward_path = Path("/logs/verifier/reward.txt")
    if reward_path.exists():
        try:
            return float(reward_path.read_text(errors="replace").strip())
        except Exception:
            pass
    return None


def main():
    output = read_text("/tmp/test_full.log")
    script = read_text("/tests/test.sh")

    statuses = parse_statuses(output)
    if not statuses:
        statuses = [("tests/roadmap.py::unknown", ERROR)]

    ratios, counts, inline_weights = parse_phase_ratios(output)
    weights = parse_weights(script, len(statuses))
    for idx, weight in inline_weights.items():
        if 1 <= idx <= len(weights):
            weights[idx - 1] = weight

    details = []
    weighted_total = 0.0
    weight_total = 0.0
    failed_names = []

    for pos, (name, status) in enumerate(statuses, start=1):
        phase_num = parse_phase_number(name, pos)
        weight = weights[pos - 1] if pos - 1 < len(weights) else 1.0
        if phase_num in ratios:
            ratio = ratios[phase_num]
        else:
            ratio = 1.0 if status == PASSED else 0.0
        contribution = weight * ratio
        weighted_total += contribution
        weight_total += weight

        if phase_num in counts:
            phase_passed, phase_total = counts[phase_num]
            message = (
                f"Phase {phase_num}: {phase_passed}/{phase_total} checks passed; "
                f"weighted contribution {contribution:.6f}/{weight:.6f}"
            )
        else:
            message = (
                f"Phase {phase_num}: status {status}; "
                f"weighted contribution {contribution:.6f}/{weight:.6f}"
            )

        if status != PASSED:
            failed_names.append(name)

        details.append(
            {
                "name": name,
                "status": status,
                "message": message,
                "score": contribution,
                "weight": weight,
            }
        )

    passed_count = sum(1 for _, status in statuses if status == PASSED)
    total_count = len(statuses)
    pass_rate = passed_count / total_count if total_count else 0.0
    total_score = parse_total_score(output)
    if total_score is None:
        total_score = weighted_total / weight_total if weight_total else 0.0

    summary = (
        f"{passed_count}/{total_count} phases passed; "
        f"weighted score {total_score:.6f}"
    )
    if failed_names:
        summary += ". Failed: " + ", ".join(failed_names[:10])
        if len(failed_names) > 10:
            summary += f" (+{len(failed_names) - 10} more)"

    result = {
        "valid": True,
        "score": total_score,
        "pass_rate": pass_rate,
        "summary": summary,
        "details": details,
        "metrics": {
            "phase_weighted_total": weighted_total,
            "phase_weight_total": weight_total,
            "source": "roadmap_structured_json",
        },
    }

    print(">>>>> Start Structured Result")
    print(json.dumps(result, ensure_ascii=False, indent=2))
    print(">>>>> End Structured Result")


if __name__ == "__main__":
    main()

What we found

The full case, with the test submissions, the independent checks and the fix. File paths refer to the repository; links open on GitHub.

Outcome: Fixed. The Phase 3 tests check only that @schemathesis.metric returns something callable, not that it returns the function unchanged; under the fixed tests a wrapper loses one test item, 1/160 of the score (0.625 points out of 100).

What the task asks

The solver modernizes the configuration layer of schemathesis 3.39.16, a tool for testing web APIs. Hidden tests, grouped into phases, grade the result. The task text tells the solver to "Treat /app/TODO.md as the authoritative task specification." TODO.md Target 3 states that the "@schemathesis.metric decorator: Registers a metric function into a registry. Returns the function unchanged." A decorator is a function that takes another function and returns a function in its place. TODO.md uses the same wording for @schemathesis.check. Category: Systems & Software Engineering.

What goes wrong

The decorator must return the function unchanged, but the original test test_metric_decorator_returns_function only asserts callable(another_metric). A wrapper that forwards calls to the function therefore scores the same as a correct decorator.

We tested three variants of metric on a minimal implementation of Target 3.

  • identity registers the function and returns it, which is correct.
  • wrapper returns a forwarding wrapper built with functools.wraps, which is plausibly wrong.
  • no_register never registers the function, which is clearly wrong.

These are the Phase 3 results under the original tests (orig) and the fixed tests (repaired).

variant=identity    tests=orig     :: 15 passed
variant=identity    tests=repaired :: 16 passed
variant=wrapper     tests=orig     :: 15 passed
variant=wrapper     tests=repaired :: 1 failed, 15 passed
variant=no_register tests=orig     :: 3 failed, 12 passed
variant=no_register tests=repaired :: 4 failed, 12 passed

Under the specification, the wrapper should lose the test item that checks identity. On the original grader it passes 15/15, the same as the correct decorator.

The effect is small. In behaviour, the wrapper is almost equivalent to the correct decorator. It keeps __name__, registers under the right name, returns the same values, and works with the collector and with hypothesis.target. The only differences are decorated is original and the presence of __wrapped__. The wrong implementation gains no advantage over a correct one and only avoids losing one item. The authors probably intended identity, since the Phase 6 test asserts result is my_func for @check; Phase 3 has no such check.

How much it matters

The effect is at most 1/160 of the total, 0.625 points out of 100. The score is Σ(weight × passed/total)/10 over six phases, and Phase 3 has weight 1. With the fixed version's 16 Phase 3 tests, a wrapper that passes k of the 15 original tests drops from k/15 to k/16 of the Phase 3 weight, a loss of k/2400; at k = 15 that is 1/160, the measured −0.006250. (In the original 15-test phase, one test is worth 1/15 × 1/10 = 1/150.)

The change does not only lower scores. A submission whose decorator returns the function unchanged but passes only k < 15 of the original Phase 3 tests rises from k/15 to (k+1)/16, a gain of (15 − k)/2400. Either change is at most 1/160 per run. Only submissions with a wrapper decorator, or with a partly passed Phase 3, score differently.

The fix

  • /tests/test_03_metric_system.py gains test_metric_decorator_preserves_exact_function_identity. The test asserts metric(f) is f and unregisters the function afterwards.
  • /tests/test.sh changes PHASE3_TOTAL and PHASE3_EXPECTED from 15 to 16.

The weights, the parser, the score scale and the 126 original tests are unchanged. In task.json.in, only judge.image_tag changes.

How we checked it

  • We ran the original grader in the original public image, pinned by digest. The grader image holds the unmodified schemathesis 3.39.16 starting code in /app and no reference solution. Each variant and the untouched starting code ran through the full original judge.eval_cmd (bash /tests/test.sh plus the structured parser), in a fresh --network none container, under both the original and the fixed tests.
  • For an independent check, the reference is the sentence of the specification in TODO.md ("Returns the function unchanged"), and the added test checks it directly. No formal model applies.
  • We repeated the side-by-side run of the original and fixed graders three times, and no outcome changed (data/paired-repeatability.md).

Limits

  • We ran no AI model or solver. The effects shown come only from test submissions that we wrote.
  • The overlay is a minimal implementation of Target 3, not a complete solution to the task, so the absolute scores are partial.
  • We examined no historical submissions, so we do not know how often real solvers write wrapper decorators.
  • We did not extract TODO.md again from the pinned work image.
  • The added test checks schemathesis.generation.metrics.metric; for the top-level schemathesis.metric, which TODO.md names, the tests still check only that it is callable, so a wrapper re-exported at the top level (for example with functools.wraps) still passes all three metric tests although schemathesis.metric(f) is f is false (local probe). Closing this would need one more assertion and a new paired run.
  • We rebuilt the package from scratch on a clean machine (evidence/runs/materialize-check-g2, status: exit=0). materialize.sh ran unchanged, both outputs matched the lock, and the built image holds the locked test files.
  • This repository does not store the hidden tests. The scripts extract them from the pinned grader image when you rerun the check.
