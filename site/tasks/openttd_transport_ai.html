OpenTTD Transport AI

Fixed Instruction–grader mismatch openttd_transport_ai

The instructions name a game function that does not exist.

SummaryThe instructionsHow it is gradedWhat we foundFiles

Summary

The task
Write a computer player for OpenTTD, a transport-company simulation game, that grows its company's value over 20 game-years on several random maps.
What goes wrong
The instructions say to maximize the result of a function, AICompany.GetCompanyValue, that does not exist in this game version; a program calling it crashes there. The supplied starter calls it in its main loop and builds nothing, so it scores 0 in either version. The instructions also say all infrastructure adds value; the game counts only stations. The grader works correctly.
How much it matters
Up to the whole score for a submission that follows the instructions and calls the missing function. Submissions that use a different function are not affected.
What we did
Fixed in a new version: the instructions and starter program name the correct function and explain how the score is read. The grader is unchanged, so each submission scores the same.
Problem category
Instruction–grader mismatch
Validation status
Prompt and starter correction: three native runs (each exit=0) show the v1 starter dying on 5/5 seeds and the v2 starter and probe running without error; v2 work image rebuilt from scratch on a clean machine (materialize-check-g3). No score above the 1e5 anchor; the shipped API pages describe a newer OpenTTD and the documented docs path is wrong (documented limitation).

What the agent is asked to do

This is EdgeBench's original task text, the work.agent_query field of tasks/openttd_transport_ai.json, from the EdgeBench dataset on Hugging Face by ByteDance Seed, licensed under CC BY 4.0. It is shown unchanged, rendered from Markdown to HTML; links to files inside the task's workspace are shown as plain text. EdgeBench's harness adds its standard instructions on how to submit (sforge/harness/evolve_scripts.py), which are not shown.

Role

You are an expert OpenTTD AI script developer. Write a Squirrel AI in my_ai/ that maximizes company value over 20 game-years, averaged across multiple random seed maps.

Files

  • my_ai/info.nut — AI metadata (class MyAI extends AIInfo, GetAPIVersion() returns "13")
  • my_ai/main.nut — AI controller (class MyAI extends AIController, implements Start(), Save(), Load())
  • docs/squirrel_reference.html — Squirrel 2.2 language reference (offline)
  • docs/noai_tutorial.html — NoAI introductory tutorial (offline)
  • docs/noai_api_docs/ — full NoAI API (115 classes, offline HTML)

Game Background

OpenTTD (Transport Tycoon Deluxe clone) simulates a transport company: build roads / rails / airports / ships, connect towns and industries, buy vehicles, manage finances. The NoAI framework runs Squirrel scripts to control a company headlessly. Your AI is the only company on the map (no competitors).

Goal

Maximize AICompany.GetCompanyValue(AICompany.COMPANY_SELF) (= vehicle value at 1.5× purchase + infrastructure value + cash − loans). Use AILog.Info(...) / AILog.Warning(...) for debugging.

Local Testing

Install OpenTTDLab (already installed). Run locally with:

from openttdlab import run_experiments, local_folder
results = run_experiments(openttd_version='13.4', opengfx_version='7.1',
    experiments=({'seed': s, 'ais': (local_folder('my_ai/', ai_name='MyAI'),),
                  'days': 365*20} for s in range(5)))

Rules

  • Write only in my_ai/ (info.nut + main.nut + optional sub-squirrel files)
  • CreateInstance() in info.nut must return "MyAI" (matching main.nut's class name)
  • GetAPIVersion() must return "13" for OpenTTD 13.x compatibility
  • Do NOT modify anything under docs/ — it's reference material
  • A baseline AI that just logs company value is already in my_ai/; improve it

What we found

The full case, with the test submissions, the independent checks and the fix. File paths refer to the repository; links open on GitHub.

Outcome: Fixed. The instructions tell the solver to maximize a game function, AICompany.GetCompanyValue, that does not exist in the pinned game version, so a script that calls it crashes, and the supplied starter program crashes at its first call to it; the fix changes the instructions and the starter, not the grader.

What the task asks

OpenTTD is an open-source transport-company simulation game. The solver writes "a Squirrel AI in my_ai/ that maximizes company value over 20 game-years, averaged across multiple random seed maps." Squirrel is the scripting language OpenTTD uses for computer players. The prompt's goal line reads: "Maximize AICompany.GetCompanyValue(AICompany.COMPANY_SELF)". It also says "A baseline AI that just logs company value is already in my_ai/; improve it". Category: Interactive Games & Simulators.

What goes wrong

The instructions name a function that does not exist. AICompany.GetCompanyValue is not in the OpenTTD 13.4 NoAI API, the interface the game offers to computer players. The supplied starter logs one line, calls it in its main loop at main.nut line 5, and crashes:

dbg: [script] [0] [S] Your script made an error: the index 'GetCompanyValue' does not exist
dbg: [script] [0] [S] *FUNCTION [Start()] myai/main.nut line [5]
dbg: [script] The script died unexpectedly.

A full run of the original grader on the starter took 63 s of wall time and exited 0, with all 5/5 requested seeds returned.

The wrapper printed CASE 0000 WA score=0 and TOTAL_SCORE 0.

  • A solver that follows the instructions and calls the named function expects to read its company value. Instead the game kills its script at that call, and the company stops acting. The score is its last positive quarterly value, or 0.
  • Local testing, which the task provides, can reveal the problem. The fault is a misleading instruction; the grader is not in error.

The instructions also misstate what is scored. The Goal line defines the target as "vehicle value at 1.5× purchase + infrastructure value + cash − loans". The grader reads the game's own company value. In the OpenTTD 13.4 source that value counts vehicles at 1.5× their value and stations, plus cash minus loan, with a floor of 1; roads, rails and other infrastructure do not count. The probe in the table below is consistent with this. With 8 stops, no vehicles and cash minus loan negative, it scores 4,975. Under the test in METHOD.md, this is a case of the agent being told a different rule from the one applied. A solver that builds track or roads expecting them to add value gets a score that leaves them out. We did not measure the size of this effect, and the rails part rests on reading the source, not on a run.

The grader itself behaves correctly. It reads company value from the game's monthly save files. In a seed-0 run there are 239 monthly saves, from 1950-02-01 to 1969-12-01, so the game runs the full 7,300 days. old_economy[0].company_value is 1 in every save, and the grader's > 1 filter turns that into 0, so a company that does nothing scores 0. With 239 saves and a final date of 1969-12-01, the "last quarterly value" is the 1969-10 quarter. The error flag from OpenTTDLab (the library that runs the games) is printed but does not affect the score.

Run time is not a concern for this run. One seed alone took 55.4 s, about 9,750 ticks/s, far above the roughly 150 ticks/s needed. The 5-seed run took 63 s against an eval_timeout of 3600 s.

How much it matters

Up to the whole score for a solver that follows the instructions and calls the named function. Solvers who test locally and use a different function are not affected.

The fix

The fixed version is in repairs/openttd_transport_ai-v2/ (the folder holding the fixed version).

  • In the instructions, the Goal paragraph of work.agent_query now says that OpenTTD 13.4 has no AICompany.GetCompanyValue and that calling it stops the script. It names AICompany.GetQuarterlyCompanyValue(AICompany.COMPANY_SELF, AICompany.CURRENT_QUARTER) for the running value, and quarter 1 for the value recorded at the start of the current quarter. It corrects the formula so that stations count, other infrastructure does not, and the floor is 1. It also states how the grader reads the score: for each seed, the value at the most recent quarter boundary before the game ends (falling back to an earlier quarter above 1, or 0), averaged over the 5 seeds.
  • In the starter, my_ai/main.nut line 5 calls GetQuarterlyCompanyValue(AICompany.COMPANY_SELF, AICompany.CURRENT_QUARTER). Dockerfile.work builds the fixed work image from the original work image's digest (image about 0.46 GB compressed); work.image_tag becomes f2e9a9fb0fff-ebv-v2.
  • The fix rests on the game's code. The OpenTTD 13.4 source defines GetQuarterlyCompanyValue as CalculateCompanyValue(c) for CURRENT_QUARTER and as old_economy[quarter - 1].company_value otherwise. The cached 13.4 program contains the name GetQuarterlyCompanyValue and not GetCompanyValue. A probe script reported has_GetCompanyValue=false has_GetQuarterlyCompanyValue=true.
  • The grader image, eval_cmd, parser and score scale (log_max, with reference points 1e5 to 1e9) are unchanged, so each submission scores the same under the original and fixed versions.

The side-by-side run used the exact original eval_cmd, 5 seeds and 20 game years (copied from paired/results.md). TOTAL_SCORE is the raw result (before conversion to 0 to 100).

  • The idle probes score 0 because an idle company's value stays at the floor of 1 (cash minus a 100,000 loan is negative), which the grader counts as 0. They show that the script survives; they do not show a positive score.
  • For both probes, on every seed, the last logged GetQuarterlyCompanyValue(SELF, 1) equals the old_economy[0].company_value that the grader used. For probe_value that is 4,975, while the running CURRENT_QUARTER value at the end was 4,858.

Scores are comparable as measurements of the same harness. They are not comparable as measures of solver ability where a solver of the original version followed the instructions and called the missing function.

How we checked it

  • We ran the original grader in the original image, pinned by digest. The exact eval_cmd, cd /home/workspace/openttd_ai && OPENTTD_N_SEEDS=5 python3 /tmp/eval_openttd.py, ran offline under timeout 2600 in the grader image (--network none --memory 6g) on an 8-vCPU host, so all 5 seeds ran in parallel. The submission was the supplied starter my_ai/ from the work image. OpenTTD 13.4 and OpenGFX 7.1 (the game's graphics set) are pre-cached in the image.
  • For the save-file check, a seed-0 diagnostic (diag1.py) calls run_experiments with the grader's own arguments and prints every save row.
  • The side-by-side run of the original and fixed versions gives the tables above. We repeated it three times with no verdict change (data/paired-repeatability.md).

Limits

  • We ran no AI model or solver. The effects shown come only from the supplied starter and probes we wrote.
  • In the side-by-side run we graded each test submission once, because the grader image is the same in both versions; the original and fixed TOTAL_SCORE columns repeat that score. The versions differ only in the starter and instructions the solver receives.
  • The only test submission with a positive raw result is a probe (4,975, far below 1e5, the lower reference point of the score scale, so 0 out of 100). Every company value up to 1e5 scores 0 out of 100, so a score of 0 does not tell a crashed script from a weak one. We did not test whether a submission can reach 1e9, the upper reference point.
  • The documentation path in the instructions (docs/noai_api_docs/) differs from the real one (docs/openttd_reference_docs/noai_api_docs/), and the supplied HTML documentation appears to be from a later OpenTTD than 13.4 (it describes AIEconomyTime and the economy quarter). A solver that calls a function described there but missing in 13.4 stops its script, like the original starter. We keep both as documented limitations, because correcting them changes the instructions (agent_query) and would need a new side-by-side run.
  • We rebuilt the work image from the package on a clean machine (evidence/runs/materialize-check-g3, status: exit=0); the built image holds the fixed main.nut with the locked sha256.
  • The ticks/s figure is for an idle script on one host. An AI running many vehicles will be slower, which we did not measure.
