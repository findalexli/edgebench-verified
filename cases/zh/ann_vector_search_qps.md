# ANN Vector Search QPS (`ann_vector_search_qps`)

**结论：** 保留（附说明）。<mark>正常的提交按文档所述方式评分，但测得的速度取决于评分器所在的机器，多次评分之间也有波动。我们按排行榜的评分器设置，把同一个正常配置隔离评分三次，得到 551–713 QPS，在分数刻度上相当于 13.3 分（满分 100，约 ±7 分）。</mark>

## 任务要求

智能体要加快近似最近邻搜索。这种搜索不必把查询与每个向量逐一比较，就能找出离查询最近的向量。任务说明写道："maximize **QPS** (queries per second) on the SIFT-1M dataset (1M × 128-d vectors, 10K queries) under the ann-benchmarks framework, while keeping **Recall@10 ≥ 0.95**"（在 ann-benchmarks 框架下，让 SIFT 数据集上的每秒查询数 QPS 尽量高，同时召回率不低于规定阈值）。Recall@10 指真实的前 10 个最近邻中，搜索找到了多大比例。

智能体只改 `ann_benchmarks/algorithms/custom/module.py`。评分器的原始结果（换算到 0–100 之前的数值）在这里就是 QPS，它按对数刻度（`log_max`）换算成满分 100 的分数。0 分的参考点是 3108 QPS，100 分的参考点是 21472 QPS。原始结果达到或超过 21472 QPS 的都得 100 分。类别：系统与软件工程。

## 我们检查了什么

评分器给正常解题者算出的，就是文档所说的结果。我们做了下面几项检查。

- 评分器的标准答案（标签和距离）在全部 10,000 个查询上都正确。
- 评分器接受一个用 FAISS flat 搜索（精确的暴力搜索）的正确测试提交，拒绝一个空的测试提交。
- 评分器拒绝一个快但不准的提交。这个提交用同一个 IVF-flat 索引，每次查询只搜一个簇（`nprobe=1`），达到 11,237–12,988 QPS，但召回率只有 0.3642。三次单独评分中，评分器每次都判它为错误答案，总分为 0。如果没有召回率检查，这个速度相当于 66.5–74.0 分（满分 100）。
- 召回率阈值按文档所述起作用。召回率统计的是返回的邻居 ID 与真实邻居 ID 有多少重合，所以距离相同的并列项算作未命中，精确的 flat 搜索召回率因此是 0.9993，不到 1.0。上游 ann-benchmarks 的做法是，只要邻居在第 10 个真实距离以内就算命中。两种统计方法的召回率最多相差 0.07 个百分点。
- 在一次评分内，评分器按文档所述保留最快的有效配置。

说明针对的是速度测量。QPS 只在一次运行中测量，而且取决于机器。IVF-flat 是一种只搜索少数几个向量簇的 FAISS 索引。我们在原始评分器上按排行榜的评分器设置（4 个 CPU、8 GiB），把同一个正常的 IVF-flat 配置评分三次，每次单独用一台新的云端工作机，得到 713、650 和 551 QPS（相对中点 ±13%；最快的是最慢的 1.29 倍）。更早之前，我们在一台本地共享机器上用 2 个 CPU 给同一配置评分，每次都与其他测试配置共用一个进程，得到 935、1,222 和 1,094 QPS（1.31 倍）。分数刻度的参考点（3108 / 21472）来自作者的硬件。

随任务发布的说明写道：QPS 取决于机器；在原始评分器上，用 4 个 CPU、8 GiB 把同一个正常的 IVF-flat 配置隔离评分三次，得到 551–713 QPS（±13%）。在对数刻度上，只要提交介于两个参考点之间，1.29 的速度比就相当于 13.3 分（满分 100，每次评分约 ±7 分）。分数刻度的参考点来自作者的硬件，所以不同机器上的分数不能直接比较。

## 影响有多大

三台 CPU 型号相同的新工作机上各做一次隔离评分，同一个正常配置的原始结果在 551 和 713 QPS 之间。刻度是对数的，`100 · ln(QPS / 3108) / ln(21472 / 3108)`，所以对任何介于 3108 和 21472 QPS 之间的提交，1.29 的速度比会让分数相差 13.3 分（满分 100）（每次评分约 ±7 分）。之前在本地机器上共用进程的评分得到 1.31 的速度比，即 13.9 分；隔离重复证实了这一影响的大小。这里正常的测试提交都低于 3108 QPS，得 0 分，所以这一影响是按刻度算出来的，没有在分数中直接观察到。本任务已记录的智能体运行得分为 23.8–59.7 分（满分 100）（`tasks/README.md`），正好落在这个区间里，所以智能体实际达到的分数段会受到这一影响。任务保留每次运行的最佳提交（`score_first`），所以评分之间的波动可能抬高一次运行记录下的最好成绩。不同机器之间的差异是否让每种算法的速度按相同比例变化，我们没有测试。满分 100 的分数在不同机器之间不能比较，同一台机器上重复评分也不能完全复现。

任务不做修改；上述说明随任务一起发布。

## 局限

- 我们没有运行任何 AI 模型或解题者。分数影响只在我们写的测试提交上展示。
- 每个 QPS 数字都来自一次运行。隔离重复用的是 CPU 型号相同的共享云端工作机。我们没有在作者的硬件或专用评分机器上做任何测量。
- 三次重复只能粗略界定波动范围；重复更多次或换用其他 CPU 型号，波动可能更大。
- 我们只重复了单线程的 IVF-flat 配置。它的 QPS（551–713）低于 0 分参考点，所以 13.3 分的影响是按刻度算出的，没有在分数中直接观察到。我们没有测试更快的或多线程的提交是否按相同比例波动。
- 评分器能否防住蓄意的恶意提交篡改评分，不在本次发布的范围内（这是 EdgeBench 的设计选择），我们没有评估。
