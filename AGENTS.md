# Working instructions

## Where things are

- `README.md`, `FINDINGS.md`, `APPLYING-FIXES.md`, `METHOD.md`, `DECISIONS.md`: the publication.
  `site/` is the website, generated by `tools/build_site.py` (overview, a tasks tab with one page per task,
  method and leaderboard pages; English and `site/zh/` Chinese, see `tools/i18n/README.md`).
- `data/decisions.json`: the authoritative decision for every task. After any change, regenerate the
  derived files: `python3 tools/build_tables.py && python3 tools/build_findings.py &&
  python3 tools/build_applying.py && python3 tools/build_site.py`.
- `cases/<task_id>.md`: one page per task. `data/paired-results.csv`: every paired v1/v2 control.
- `repairs/<task>-v2/`: repair packages (patch, `materialize.sh`, Dockerfile `FROM` the original
  image digest, `task.json.in`, source lock, paired results).
- `evidence/`: `reviews/`, `scripts/`, `formal/` (Lean 4 + TLA+), `runs/` (E2B jobs and ledger).
- `tasks/`, `sforge/`: EdgeBench's original task definitions and harness, byte for byte (`sforge/UPSTREAM.lock`, checked by `python3 tools/check_upstream.py`). `tools/harness_compat/` keeps the earlier audit's modified harness as a record only.
- `.internal/` (gitignored): working ledger, internal-only material, image-file copies. Never commit it.
- The earlier automated audit is preserved at Git tag `earlier-audit-final`.
- Skills: `.agents/skills/edgebench-evidence-audit/` (task reasoning) and
  `.agents/skills/e2b-efficient-audits/` (cloud execution).

## Scope (user decisions, 2026-10-12)

- Count a defect only if a good-faith solver is scored wrongly or non-repeatably. Scorer tampering
  by a deliberately malicious submission is an EdgeBench design choice and out of scope; such notes
  stay in `.internal/` and out of commits.
- Decisions: retain, retain with note, repair (v2: new version, original superseded), exclude.
  Trace every defect to the final normalized score before deciding.
- Never invent score anchors; keep them with a stated limit or set them from exactly computable values.

## How to work

- Treat every claim as a hypothesis; reproduce it on the original, digest-pinned evaluator with a
  good control, the trigger and a bad control; use an independent oracle (exact arithmetic, a second
  implementation, Lean 4, TLA+) where it settles the question.
- A repair is accepted only on a paired v1/v2 run of the same inputs.
- Heavy native work runs on E2B (`tools/e2b_run.py`, at most 8 GiB per worker on this account).
  The local host has 15 GB: one heavy local job at a time, under
  `exec 9>/tmp/ebv-heavy.lock && flock 9`, in a `--memory 4g` container. A ledger "closed" event is
  not completion; check `status: exit=0` and collected results.
- Before committing, run `python3 tools/check_publish.py` and stage an explicit file list:
  no image-file copies, no tamper material, no credentials.
- No paid API fallback, usage resets or third-party contact without the user's authorization.
  Never prune or change global Docker state.
