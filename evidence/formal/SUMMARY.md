# Formal results

Every task with a Lean 4 or TLA+ result. Each row links to a note that states the claim, the model and its link to the grader code, the counter-check that must fail, and the limits. All results rerun with `python3 tools/check_formal.py` (log: [RECHECK.md](RECHECK.md)).

| Task | Tool | Result | Covers | What is proved or checked | Limit |
| --- | --- | --- | --- | --- | --- |
| [SMT Solver](notes/smt_solver.md) | Lean 4 | proved | fix | On the published pattern the original checker accepts no answer at all, although the formula is satisfiable. The fixed checker accepts an answer only if the formula is satisfiable, and accepts every correct answer written with ground keys that cover every value the answer uses. | A fragment with one sort, one one-argument function, let, =, not and and; not define-fun, ite or arithmetic |
| [Order Addition Permutation Optimization](notes/order_addition_permutation_optimization.md) | TLA+ | model-checked | fix | With the original checksum a run always keeps its first valid submission (under the task's highest-pass-rate-first rule); with the fixed one it keeps the highest-scoring valid submission. Checked over 5.4 million states, and against the real selection code on 112,944 runs. | Runs of up to four submissions and three score values |
| [Triangulation Coloring Optimization](notes/triangulation_coloring_optimization.md) | Lean 4 | proved | fix | The fixed flip rule holds exactly when the quadrilateral is strictly convex, and an accepted flip never folds the mesh. On a valid triangulation it forbids no flip the README allows. The original accepts the published folding flip. | One flip at a time; not the whole mesh; not the CPU-quota cap on cases run at once (checked by runs) |
| [Equivalence Class Divide and Conquer](notes/equivalence_class_divide_and_conquer.md) | Lean 4 | proved | fix | The original checker counts the true cost minus the size of the last operation's target; the fixed one counts it exactly. The two verdicts differ exactly when the cost lies between the limit and the limit plus that size. | The per-state sizes are taken as given; that code is identical in both versions |
| [College English Exam Bank](notes/college_english_exam_bank.md) | Lean 4 | proved | fix | The fixed grader never scores an assessment that leaves out a rule, gives exactly the original total for every assessment it accepts, and never gives full marks to a rule whose row records a deduction. The proof found three gaps in the first version of this fix and a probe of the real code found a fourth; the fix was then revised. | Text fields reduced to yes/no; deductive rules only (all 12 here); the proof starts from an already-parsed assessment |
| [Graph Node Classification](notes/graph_node_classification.md) | Lean 4 | proved | fix | The fixed grader accepts a file exactly when every test node has one integer class, and then scores it as the original does. A general lemma shows that keeping the best submission can turn added variance into expected gain; no gain for a real solver was shown. | Four ASCII control characters behave differently in Python; the size check is not modelled |
| [FFmpeg swscale Reimplementation](notes/ffmpeg_swscale_reimplementation.md) | Lean 4 | proved | fix | Under the fixed grader a failing or unverified timed call never raises the score, and submissions whose timed calls all verify score exactly as before. The original pays a failed call as if it succeeded. | Real arithmetic rather than IEEE doubles; image quality treated as pass or fail |
| [Schemathesis Datagen Pipeline](notes/schemathesis_datagen_pipeline.md) | Lean 4 | proved | fix | The fixed date test accepts exactly the specification's dates: a real calendar date, a matching weekday and a valid time (with 23:59:60 allowed on any date). Python's weekday rule equals Zeller's congruence, and agrees with Python on all 3,652,059 dates in years 1 to 9999. | The regular expression is modelled by a hand-written parser |
| [CTA Risk Budget Optimization](notes/cta_risk_budget_optimization.md) | Lean 4 | proved | fix | The fixed check is exactly the 40% test of the risk policy on yuan values; when overseas positions are exactly the dollar-priced ones and the dollar rate is at least 1, it can only lower credit. The published position is rejected by the fixed check and accepted by the original. | The exchange-rate lookup by date is not modelled; the overseas-means-dollar condition was checked on the task's data, not proved |
| [Integer Compression Codec](notes/integer_compression_codec.md) | Lean 4 | partly proved | fix | No submission can score above 320 raw; the fixed scale maps the starter's documented score to 0 and that maximum to 100. The regraded real submission's 160.76 and 50.08 are exact. The fix's main change, measuring the starter in the same run, is not modelled. | Scale arithmetic only; timing noise is outside the model |
| [Lean Analysis Proofs](notes/lean_analysis_proofs.md) | Lean 4 | partly proved | fix | Two statements the agent must prove are false, refuted inside the task's own image against its own definitions. Both corrected statements are proved. | Covers the two corrected statements, not the removal of compiler-generated and placeholder targets |
| [Tree Block Partitioning](notes/tree_block_partitioning.md) | TLA+ | model-checked | fix | The original library computes v *= v wrongly; the fixed library is correct whether or not the operands are the same object. | Arithmetic modulo 4 instead of 2¹⁶ |
| [Jagua Nesting Optimization](notes/jagua_nesting_optimization.md) | Lean 4 | partly proved | fix | For axis-aligned rectangles, a closed-form version of the fixed criterion rejects exactly the pairs whose interiors overlap beyond its 1e-6 tolerance. The modelled slab algorithm matches it on every published witness and on all 441 placements of two squares. | The algorithm itself is checked only on those cases; general polygons, rotations and strip bounds are not covered |
| [Exchange Core Throughput](notes/exchange_core_throughput.md) | Lean 4 | partly proved | finding | The original correctness check depends only on overall money balance and final order books, so it cannot detect a fee swap or dropped messages that leave the final books unchanged (as observed in all 50 rounds). | Unchanged final books is observed, not proved; the fix relies on the project's own tests, which cannot be proved here |
| [Treant Forest](notes/treant_forest.md) | Lean 4 | partly proved | numbers | Each case scores at most 2N², so a total of 92,304 scores exactly 2543510/121003 on the original scale; the fixed scale and the converted leaderboard values follow exactly from the published (one-decimal) scores. | The total 92,304 is taken as an input; conversions inherit the table's rounding; two kinds of run are converted only approximately |
| [Borden Source Inversion](notes/borden_source_inversion.md) | Lean 4 | proved | numbers | The fixed scale and every converted leaderboard value follow exactly from the published (one-decimal) scores. | Only the change of scale; the physics convention is not formalizable |

| [OpenRCT2 Theme Park AI](notes/openrct2_theme_park_ai.md) | Lean 4 | proved | numbers | 992 game days need about 1,658 seconds at the model rate and 1,661 to 1,705 seconds at the measured rates, against a 120-second budget per scenario. | Arithmetic only |
| [Schemathesis Config Modernization](notes/schemathesis_config_modernization.md) | Lean 4 | partly proved | numbers | Every published score change is exact, and fully passed or fully failed test groups score the same in both versions. | The identity test itself is not formalized |
