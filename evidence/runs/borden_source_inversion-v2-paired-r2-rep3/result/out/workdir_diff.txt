> ## Judge forward model (exact, v2)
> 
> `forward_model.py` in this directory is a solver-visible copy of the judge's forward
> model. Its function bodies are identical to the judge's private copy (only the header
> comment differs). The judge does not import your copy, so editing it cannot change your
> score. Call `simulate_from_answer(answer, wells_df, times_days, public_config)`; it
> returns `concentration_predicted_mg_L` for every well and time. It does exactly this:
> 
> - Source sub-points: `nx x ny x nz = 5 x 5 x 1` points from
>   `np.linspace(center - half_length, center + half_length, n)` on each axis. Because
>   `nz = 1`, the single sub-point plane sits at **`z = z_center - half_length_z`**
>   (the bottom face of the box, not its centre).
> - Release times: `release_steps = 9` instantaneous pulses at
>   `t_start + np.linspace(0, max(duration, 1), 9)`.
> - Each of the 225 pulses is an instantaneous 3-D Gaussian point source with
>   `D_L = alpha_L*v`, `D_TH = alpha_TH*v`, `D_TV = alpha_TV*v` (Dm = 0, R = 1,
>   lambda = 0) and pulse amplitude `(C0 / 225) * q_source_m3_per_day * fallback_source_scale_factor`
>   (that is, `C0 * q * 1000 / 225`). Contribution:
>   `amp / ((4*pi*t)**1.5 * sqrt(D_L*D_TH*D_TV)) * exp(-(x-xs-v*t)**2/(4*D_L*t) - (y-ys)**2/(4*D_TH*t) - (z-zs)**2/(4*D_TV*t))`.
> - Porosity is **not** used, total released amount does **not** depend on `duration`,
>   and the result is reported directly as mg/L with no further unit conversion.
>   `C0` is therefore an effective intensity in this convention, not a physical
>   injected concentration; a textbook ADE model with porosity dilution and mass
>   rate x duration will put the same plume at a different `C0`/`z_center`.
> 
> The hidden labels were generated by this same model, so a fit that uses it is scored on
> the same convention it was fitted in. The inverse problem is only weakly identified by
> the public wells; a careful least-squares fit with this model is not expected to reach
> the maximum score.
